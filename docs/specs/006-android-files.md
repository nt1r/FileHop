# Spec 006：Android 文件传输与本地下载

状态：已确认，待实现。本文为 Android 文件传输与本地下载的权威需求、技术契约与验收依据；确认不代表已经实现。

关联：[产品基线](../product.md) · [路线图](../roadmap.md) · [Spec 002](002-desktop-file-transfer.md) · [Spec 003](003-server-file-management.md) · [Spec 005](005-android-text-loop.md)

本文件为该切片唯一 Spec，尚未创建远程 Issue。

## 1. 目标与范围

在 Android 文本客户端基础上，完成文件选择上传、认证下载、服务器文件管理以及本机副本打开与删除。服务端发送身份、容量预留、上传停止、幂等性和服务器实体删除规则复用 Spec 002、003。

不包含目录上传、系统分享至 FileHop、导出/另存公共目录、断点续传、后台可靠传输、多服务器管理、外部原地编辑、修改检测、内容 Hash、批量删除或整个手机文件系统管理。

## 2. 已确认的产品行为

### 文件选择与上传

- 系统文件选择器支持多选及追加，选择后自动上传，不增加发送确认步骤。只访问用户选择且已授权的 URI，不要求真实文件路径，不申请管理所有文件权限。
- 最多 3 个活动上传，其余等待；每个文件独立展示进度、停止及结果。等待项可移除，文本发送独立。
- 上传队列及源 URI 引用保存在进程内存，旋转不丢失，进程终止不恢复或自动重传。
- 从选择器返回先通过 Spec 005 的会话和兼容检查，再开始上传。失效时保留进程内选择，重新登录后协调已有任务再继续等待项。
- 每笔上传复用 send_id、attempt_id、容量预留及字节数校验规则；失败由用户显式重试，结果未知先查询，不自动作为新发送重传。
- 进度 100% 后等待服务器确认，停止不等于撤回，已提交文件不因停止或退出删除。

### 下载及重复副本

- 用户每次主动下载均可创建独立本地副本，不因已经下载或名称相同而拒绝；不检测旧副本是否修改。
- 同一服务器文件正在下载时不启动第二笔下载，而是定位已有任务；完成后可再次主动下载。
- 每个副本有独立本地 ID，内部使用唯一实体名称；显示/外部打开名称冲突时依次使用 `notes.txt`、`notes (1).txt` 等，不覆盖原副本。
- 下载任务失败后从头重试，复用该任务身份，不额外产生多个完成副本；新的一次主动下载则是新任务。
- 显示进度及停止入口；先写临时文件，完整接收并校验声明大小后才成为可打开副本。仅比对大小，不承诺内容 Hash 完整性校验。
- 停止与完成提交由本机任务状态协调：停止先取得终止资格则禁止提交，完成先提交则保留副本，不误报已停止或自动删除。退出后的完成结果不能重新展示敏感界面。
- 空间不足或中断不报告完成，清理临时文件且不删除其他完整副本。重启清理遗留未完成任务，不自动续传。

### 本地保存与打开

- 保存到应用专属持久文件目录，不使用缓存目录或公共 Downloads；默认不让用户逐次选择目标目录。
- “本地下载”页显示名称、大小、下载时间，支持打开与单个删除。删除前说明仅影响当前设备，不影响服务器或其他副本。
- 卸载 App 或清除应用数据会删除应用管理的副本，界面/说明须明确告知；副本及本地记录不参与系统自动备份或设备迁移。
- 通过安全授权 URI 供外部应用打开，只承诺打开，不承诺对原副本原地修改；外部应用另存的副本不由 FileHop 管理。
- 没有可用处理应用时提示，不执行文件或自动安装 APK，不增加分享导出入口。
- 不按文件名认定内容相同，不提供修改监控；任何既有副本都不因再次下载被覆盖。
- 外部应用已获得读取权限后，本地删除不能保证收回它已读取的数据或副本；不套用服务器活动下载禁止删除规则。本地删除完成表示受管路径已移除且索引删除已提交，不承诺外部打开句柄立即关闭或磁盘空间立即释放。

### 前后台与认证

- 只保证前台传输。短暂切后台不主动取消已开始传输，但暂停启动新的上传和下载任务。
- 不使用前台服务、WorkManager 或系统 DownloadManager 代管任务；后台是否能继续取决于系统，不能宣称可靠完成。
- 回前台先验证会话和 API 兼容性，协调已有任务，再继续等待上传队列；失败任务不自动重传。
- 凭证自然到期不主动截断已认证传输，但不开始新请求；重新登录之前隐藏敏感名称和进度。
- 主动退出清理传输队列、停止本机读写并尽力终止未提交服务器上传，不删除已完成本地副本；服务端未知状态仍按既有超时清理规则处理。
- 未登录或前台会话尚未验证时，不展示本地副本名称、不提供应用内打开入口。这只是 UI 访问限制，不是文件加密，也不能撤销此前外部应用已取得的数据。
- 因此冷启动或回前台时服务器不可达，会暂时阻止通过 App 打开已有本地副本；使用说明须明确这一限制，不宣称提供离线本地文件管理。
- 服务器文件已删除或异常不影响已完整保存的本地副本；重新登录同一服务器后可继续在本地下载页操作。

### 单服务器简化

- 首次确认服务器地址后固定，退出/重新登录仍连接同一地址；取消此前 Spec 005 的应用内服务器切换能力。
- 更换服务器需通过系统清除应用数据并重新配置，明确其会删除本地副本。开发版与正式版依靠独立 application ID 隔离。
- 不做跨服务器副本归属、实例身份检测或域名重建迁移协议。同域名后端替换/重建时，不自动关联本地副本与新服务器记录；需要全新环境应清除应用数据，本版不承诺自动检测。

### 服务器文件管理

- 独立“服务器文件”和“本地下载”入口，两个删除操作分别说明影响范围。
- 服务器页复用 Spec 003 的列表、容量、下载、单个删除、状态版本与刷新规则。
- 服务端有活动读取时拒绝删除，不排队自动删除；未知删除结果仅自动查询，不自动重发 DELETE。
- 历史文件消息提供实际上传/下载及状态展示，替代 Spec 005 的不支持文件操作占位。

## 3. 已确认的技术契约

### URI 读取及上传准备

- 使用 Storage Access Framework 的可多选文档选择方式，流式读取 ContentResolver 提供的字节，不把 content URI 当成本地路径，不申请广泛存储权限。
- 不依赖永久 URI 权限来恢复队列；只在当前任务持有必要权限，正文和队列不写系统保存状态。
- 文档提供方可能不给长度、不能重新打开或内容会变化。先为进入活动名额的任务流式暂存一个有界、私有、不可变的上传快照，计量到真实大小后再向服务器申请额度。
- 暂存计入该任务的活动名额，等待队列不提前复制。先通过 Spec 002 的认证限制接口获取 max_file_size_bytes，再按服务器限制及本地暂存预算准入，不硬编码 100 MiB 为所有实例上限。限制未知时暂停新暂存；超出有效限制立即停止清理，不把大文件完整加载进内存，云文档读取失败明确提示。
- 暂存完成不代表服务端一定接受；如果配置快照已过期，以服务器准备请求的拒绝和新限制为准，保留明确失败状态，不自动换发送身份反复上传。
- 原始名称/MIME 只作不可信元数据，快照完成后固定字节、名称、来源标签和发送身份。重试不重新读取可能已变化的 URI；更换源文件视为新发送。“不可变”仅保证本应用在快照完成后不修改它，不保证外部源在复制期间未变化，不提供源文件原子快照承诺。
- 独立限制本地上传暂存总量，计入活动写入、已完成快照、失败后保留快照及待清理实体，而非只计算 3 个活动任务。预算是可调资源参数，实现前结合单文件上限明确默认值并验证；不得将服务器 1 GiB 额度直接视为手机预算。
- 本地暂存准入及按块计量须原子协调，既有预留与实际字节不重复计数；未知长度最多按单文件上限预留，再在完成时结算实际大小。预算不足时明确失败并提示移除失败任务或稍后重试，不无界复制或无限自动等待。
- 可重试的失败任务保留原快照，并提供明确的移除入口；不静默清理后仍显示可直接重试。若快照异常丢失或被清理，禁止沿用原发送身份读取源文件重传，提示检查服务器结果并重新选择作为新操作。
- 成功或用户放弃后，在本机旧读取/写入者退出后清理上传快照，实体清理完成才释放暂存预算；放弃不自动终止服务器已接受操作，未知结果仍保留必要的进程内协调状态。
- 进程终止后的快照是可清理临时数据，不是持久队列。启动先协调并清理遗留暂存，再开放新暂存任务；清理失败的实体继续计入预算，不静默视为已释放。
- 暂存只解决不可重复读取和大小预留，不提供分片/续传/内容去重，会额外占手机空间，空间不足须明确提示。

### 本地文件与记录一致性

- 本地索引数据库只存副本元数据及操作状态，不作为远程消息缓存。完成记录至少包含本地副本 ID、原服务器文件 ID、显示名、实际大小、完成时间和安全相对路径。
- 副本始终通过本地 ID 打开/删除，服务器文件 ID 仅为来源信息，不用于去重完成副本或自动覆盖。
- 使用应用内部 filesDir 下的受限子目录保存完成副本；临时目录及本地索引同样私有且排除备份。
- 下载任务及实体使用独立 UUID；同名展示名称分配受本地事务保护，后缀插入末尾扩展名前，无扩展名则加在名称尾部。
- 下载响应必须是成功的认证文件响应；401/错误 JSON/重定向不能当作文件保存。复用 Spec 005 的重定向及凭证保护，要求可核对的文件字节长度，失败从头重试。
- 完整下载后持久写入、移动到正式本地路径，再提交完成记录，最后向 UI 报告完成。文件系统与本地数据库不是同一事务。
- 本地下载任务有独立的执行代次，每次从头重试创建新代次及独立临时路径，保持原任务身份。旧执行的回调、写入、清理和提交不得影响新代次；同文件互斥要等旧执行真正结束后才解除。
- 停止与完成提交通过任务级串行裁决协调，提交临界区内确定胜者。停止先胜则终结该代次，阻止完成记录提交，等待写入者退出并清理包括已移动但未提交的实体；完成先胜则保留副本，停止不再撤销。
- 主动退出使用相同终止规则，清理界面与操作实体分离；已完成副本保留，迟到响应不得恢复界面或解锁会话。
- 崩溃恢复以完成记录为准：未提交完成记录的临时/孤立实体清理，不自动产生已下载副本；已有完成记录但实体缺失/明显异常时显示本地不可用，不自动重新下载。
- 本地删除先持久标记删除中并禁止新的应用内打开，再尽力撤销该副本已有 URI 读授权、清理实体；移除路径成功后提交索引删除并从列表移除。不等待外部既有句柄关闭，不承诺其已读数据被撤回。
- 删除状态与应用内打开准入协调，不能在接受删除后又由本应用授予新的打开权限；旧外部句柄不在此准入保证内。
- 删除中崩溃后启动继续清理；实体已移除但索引未提交时，确认路径不存在后完成索引删除。权限和 I/O 错误不能当作不存在；失败保留可重试状态，不谎报完成或已释放物理空间。
- 完成副本的本地 ID、实体路径和 URI 标识不复用，避免旧授权意外指向后来的新文件。恢复清理和新下载写入隔离，启动协调完成前不开放新的下载写入。

### 打开、凭证与权限

- FileProvider 仅暴露完成副本的特定目录，禁止宽泛根路径、临时上传/下载目录或数据库目录；默认不导出，按单次打开授予 URI 读权限，不授予写权限。
- 外部打开使用安全名称与谨慎 MIME 映射，通过系统选择处理应用；未知类型允许提示无处理程序，不自动安装或执行。
- Content URI 不包含服务器 Token，不把认证文件 URL 交给外部应用；外部应用读取的是已保存本地副本。
- 不能把界面登录门槛或撤销 URI 授权当作已读取内容的远程擦除。备份排除覆盖 Android 支持版本的云备份和设备迁移机制，且须实测。

### 调度与资源

- 上传暂存、准备、传输、未确认活动状态共同受页面/进程的 3 个活动上传名额约束；服务器容量预留仍由服务端原子处理，暂存不提前预留服务器额度。
- 同一 server file_id 的下载任务互斥直到成功/失败/停止被本机可靠终结。独立限制最多 3 个活动下载，超过时明确提示稍后重试，不新增下载等待队列。
- 旋转不新建任务、回前台不重复发起 PUT/GET；进程终止后不自动发起任何下载。用户重新进入、完成会话验证并再次点击下载时创建新任务，从头传输；原未完成任务残留由启动协调清理。
- 服务器上传身份若已丢失，先让用户检查历史再创建新操作。启动恢复必须区分旧残留与新任务，不允许并行扫目录误删新写入文件。
- 主动退出要取消读写并等待旧写入者退出后清理，不以删除路径代替取消写入。后台暂停新调度不等同于终止已认证请求。
- 文件 HTTP 客户端复用 Spec 002 的连接/无进展/整体期限分类，不继承文本 JSON 的 15 秒整体超时；URI 提供方读取也须可取消且有独立的无进展处理，不无限占用名额。
- 本地可用空间检查只是预检，运行中 ENOSPC/I/O 错误必须安全处理；临时与完成副本共同消耗手机磁盘，不套用服务器 1 GiB 额度。

## 4. 验收场景

| 编号 | 场景与预期 |
| --- | --- |
| F01 | 系统选择器多选/追加自动上传，3 个活动名额含暂存，等待项可移除，文本仍可用 |
| F02 | 未知大小、云文档、不可重复读取及权限失败明确处理；连续失败超过活动数时保留快照总量仍受预算约束，清理失败不提前释放预算，源复制过程不虚假承诺原子快照 |
| F03 | 文件字节和元数据在同次重试中固定；重复/迟到请求遵循 Spec 002，不重复消息或预留 |
| F04 | 同文件活动下载不重复；完成后可再次下载，重名加后缀，各副本独立且不覆盖，失败重试只产生一份完成记录 |
| F05 | 空间不足、错误响应、字节数不符不产生正常副本；停止先胜不提交，完成先胜保留；旧代次不能写入/清理新代次，不影响其他完整文件 |
| F06 | 下载及本地删除的实体/索引边界杀进程，恢复继续清理但不自动下载，已完成副本保留；启动协调不会误删新任务文件 |
| F07 | 旋转保留任务，后台不启动新任务且无可靠后台承诺；回前台验证/协调后继续等待上传，进程结束不恢复队列 |
| F08 | 到期、主动退出、登录恢复不误重传；退出保留完整副本但不展示敏感列表，迟到回调不能解锁 |
| F09 | FileProvider 仅暴露完成副本，外部仅获读权限，无可打开应用明确提示，不泄露远程凭证或执行文件 |
| F10 | 服务器删除不影响本地副本，本地删除不影响服务器/其他副本；两类确认文字和状态明显区分 |
| F11 | 清除应用数据/卸载删除专属副本，不由备份迁移恢复；正常覆盖更新保留完成副本，开发生产安装隔离 |
| F12 | 首次地址确认后无切换入口，不做跨实例归属；清除数据后可重新配置，原副本不会混入新环境 |
| F13 | 服务器管理复用活动下载拒绝删除、未知结果查询、状态版本防回退及容量展示 |
| F14 | 本地索引缺实体显示不可用不自动下载；已接受删除不能新授予打开权限；路径/URI 不复用，旧外部句柄可能继续读但不阻塞本地删除，也不承诺立即释放磁盘空间 |
| F15 | 暂存失败项可移除，清理后不可再用原任务读取变化源重传；网络不可达的前台会话检查不解锁本地列表，提示与使用说明一致 |

## 5. 审阅与完成条件

审阅修订已补齐本地暂存总预算、停止/完成裁决和执行代次、本地删除持久恢复及外部读取边界、进程终止后仅用户重新发起下载的规则。整份 Spec 已最终确认，包括最多 3 个活动下载的默认方案；不新增下载队列、修改检测或后台服务。

前序 Spec 已补齐 Android 文件阶段扩展引用，不改变已经确认的服务器行为。实现并通过本 Spec 及跨端端到端验收后，完成当前六份 Spec 的核心项目范围。
