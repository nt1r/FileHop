# Spec 006：Android 文件交换

关联：[产品基线](../product.md) · [Spec 002](002-desktop-file-transfer.md) · [Spec 003](003-server-file-management.md) · [Spec 005](005-android-text-loop.md)。本文件是本切片唯一权威来源，实施 Issue 只引用范围和验证编号，不重复维护完整需求。

## 1. Problem Statement

桌面 Web 已能交换文件，Android 文本客户端目前只能显示文件消息占位，用户尚不能在手机上发送文件或保存 Web 发来的文件。需要完成日常手机与 Web 双向文件交换，而不是建设移动网盘或本地文件管理器。

## 2. Solution

在现有 Android 消息流中提供系统文件多选、追加与串行上传，从文件消息下载到用户通过系统选择的位置。展示真实的进度与结果，提供必要的中断、取消和未确认结果手动处理；保存后交给系统文件管理器打开、删除。

保持单人自用、先用起来：复用已有认证和文件协议，只保证前台传输，不增加持久任务恢复或独立服务器文件管理页。

## 3. User Stories

1. 作为用户，我希望通过系统文件选择器多选并追加文件，以便连续向共享消息流发送多个文件。
2. 作为用户，我希望选中文件后自动串行上传，以便不必逐个确认且不会同时启动多个上传。
3. 作为用户，我希望移除尚未开始的等待项，以便不发送误选的文件。
4. 作为用户，我希望看到当前文件的进度与结果，以便区分正在传输和服务器已确认保存。
5. 作为用户，我希望在文件过大、空间不足或所选文件不可读取时得到明确提示，以便调整后重新选择。
6. 作为用户，我希望中断当前上传，以便停止本机继续传输，并知道这不等于撤回服务器文件。
7. 作为用户，我希望在上传结果未确认时手动查询原发送，以便避免自动重传导致重复消息。
8. 作为用户，我希望明确失败后继续处理其余等待项，以便一个失败文件不阻塞后续发送。
9. 作为用户，我希望需要重发失败文件时重新选择，以便发起一次明确的新发送。
10. 作为用户，我希望结束本轮上传并清空队列，以便退出当前批次，同时知道重新选择可能重复发送。
11. 作为用户，我希望从文件消息发起下载并通过系统选择保存位置，以便获取 Web 或手机发送的文件。
12. 作为用户，我希望在位置选择器中取消而不开始下载，以便放弃误触的操作。
13. 作为用户，我希望区分下载中、保存中和保存成功，以便知道文件何时真正写入所选位置。
14. 作为用户，我希望在下载或保存期间主动取消，以便停止尚未完成的操作。
15. 作为用户，我希望在下载或保存失败时得到真实提示及可能残留的说明，以便重下或通过系统检查不完整文件。
16. 作为用户，我希望同时进行一个上传和一个下载，并继续发送文本，以便独立操作不相互阻塞。
17. 作为用户，我希望在上传结果未确认时仍可下载其他文件，以便不必先解决上传才能获取已有内容。
18. 作为用户，我希望通过系统文件管理器打开和删除已保存的本地副本，以便不依赖 FileHop 的登录或服务器在线状态。
19. 作为用户，我希望服务器文件删除后仍保留完整本地副本，以便本地文件不随服务器清理而丢失。
20. 作为用户，我希望旋转屏幕时不重复启动传输，以便正常操作手机。
21. 作为用户，我希望切后台时不主动取消已经开始的文件任务，但暂停启动新任务，以便维持简单的前台传输行为。
22. 作为用户，我希望进程终止后不自动恢复或重发文件，以便重新进入时不会发生意外发送。
23. 作为用户，我希望登录失效时停止未完成的本机传输，重登后手动处理未确认发送或重新下载，以便不自动恢复旧文件批次。
24. 作为用户，我希望主动退出时清空敏感上下文并停止本机传输，以便结束当前登录且不误以为已撤回服务器或系统保存的文件。
25. 作为用户，我希望需要释放服务器空间时先使用 Web 服务器文件页，以便无需等待 Android 管理页就能完成文件交换。

## 4. Implementation Decisions

### 既有能力与接口复用

- 在现有 Kotlin + Jetpack Compose 客户端扩展文件消息展示、传输与系统选择/保存能力，沿用 Spec 005 的原生认证、凭证保护和来源标签规则；不提前锁死内部模块或状态机组织。
- 复用 Spec 002 的限制查询、发送准备、单轮内容上传、原身份结果查询和认证下载接口，不引入新后端协议或数据库结构。限制未知或离线不启动新上传；单文件限制、空文件及元数据规则保持 Spec 002 不变。
- 文件传输使用流式读写，不套用文本 JSON 请求的短总超时；上传和下载的期限语义沿用 Spec 002，敏感请求不自动跟随重定向。
- 文件消息展示名称、大小、来源及已知状态，并提供可用文件的下载入口。状态版本合并及手动刷新/重入后的状态校正沿用 Spec 003；不把新增消息轮询变成删除状态轮询，实际下载可用性以服务器为准。

### 上传

- 通过系统选择器多选及追加后，按选择顺序自动发送，在进程内排队并逐个上传；最多一个活动上传，包含暂存和未知结果协调。等待项不申请服务器额度，也不提前复制。
- 使用 ContentResolver 流式读取所选 URI，不假定真实文件路径，不申请全盘管理权限。
- 需要获取实际大小或稳定当前传输载荷时，对当前文件生成私有临时快照。只有一个快照；按服务端单文件限制和本机可用空间限制读取，超限或磁盘不足明确失败。不得将完整文件读入内存。
- 在准备请求前固定元数据和发送身份；需要快照时，先完成快照，再固定元数据和发送身份并发起准备请求。复用 Spec 002 的单轮协议；失败后重新选择属于新发送，不保留快照供同次重传。
- 明确失败后可继续等待项，重发须重新选择；结果未知暂停队列，由用户手动查询或结束本轮，不自动查询或保留一组失败快照。不建设独立原子暂存额度账本。
- 等待项可移除；结束本轮时中断本轮上传的本机读写、清理上传快照和全部上传队列上下文，不再协调旧任务。未知服务器结果不能当作已取消；提示先检查历史，再选择是可能重复的新发送，由服务器额度与资源限制兜底。
- 上传成功、明确失败、结束本轮或进程重启后清理临时数据；清理失败提示并暂停新的暂存，用户处理后重试。不恢复持久队列。
- 显示进度和本地“中断传输”入口；100% 后等待服务端确认，中断不调用服务端 stop，也不证明文件不会保存。服务端容量、安全清理和认证语义保持 Spec 002 不变。

### 下载与系统保存

- 最多一个活动下载，不建立下载等待队列；完成或结束当前下载后可以再次主动下载。上传和下载的限制独立，允许一个上传与一个下载同时进行；上传结果未确认只暂停上传队列，不阻止下载，文件传输不限制独立的文本发送。
- 用户通过系统创建文档流程选择保存位置；取消选择直接结束，不报错、不开始下载。返回应用前台后，先以认证请求下载到私有临时文件，核对成功响应及字节数，再复制到选定 URI；全部写入并关闭成功后才报告保存成功。
- 应用内展示进度，区分“下载中”和“保存中”，不把网络接收完成当作保存成功。提供“取消”入口，覆盖下载及写入系统保存位置的过程；取消按下述失败或中断规则处理，不承诺撤回已经保存完成的文件。
- 错误响应、重定向或认证失败不能作为文件保存，不把带 Token 的远程 URL 交给外部应用。
- 下载或写入系统目标失败、中断时如实提示，清理私有临时文件；系统目标可能留下不完整文件，尽力移除，并提示用户在文件管理器检查。不承诺跨文档提供方的原子保存、自动恢复或撤回覆盖。
- 系统目标全部写入并关闭成功后，清理本次下载的私有临时文件；临时文件清理失败如实提示，但不把已成功保存的本地副本改判为保存失败，也不因此删除该副本。
- 保存位置、同名和覆盖由系统选择流程及提供方处理，不维护应用内重名分配表；用户应选择新文件，避免覆盖重要内容。
- 完成副本由系统管理，不依赖 FileHop 登录或服务器在线才能打开。服务器删除不影响它；卸载/清除 FileHop 数据不主动删除系统保存的文件，实际保留与备份由目标提供方决定。
- 不保留副本索引、长期 URI 授权或应用内打开管理入口。再次下载是新操作；失败从头重下。

### 生命周期与服务器管理

只保证前台传输；后台暂停新任务，不主动取消已开始传输，不引入前台服务或 WorkManager。一个文件从暂存到上传确认，或从下载到保存完成，分别属于同一个已开始任务；切后台不主动暂停其后续步骤，但不保证系统允许完成，也不启动下一个文件任务。从系统选择器返回后，在应用前台启动新任务。旋转不重复启动，进程终止后不自动重发；恢复时清理私有临时数据即可，不重建任务数据库。

客户端确认认证失效时，中断本机上传、清空等待项和文件引用/快照，提示需重新选择；同时中断尚未完成的下载或保存，清理私有临时数据，对未完成的系统目标尽力清理并提示可能残留，已保存成功的本地副本不受影响。只保留草稿及未确认发送身份供重登后手动处理，不自动恢复上传队列或下载；下载须由用户重新主动发起。此规则不改变服务端在请求开始时鉴权、不因凭证途中自然到期主动截断已认证请求的约定。

主动退出清空敏感上下文并中断本机传输，不请求服务端停止。凭证保护和旧响应隔离沿用 Spec 005，不承诺退出能撤回服务器已提交消息或系统已保存文件。

首版从文件消息下载即可；独立 Android 服务器文件管理页不作为手机文件闭环前置，清理服务器空间可先使用已实现的 Web 页。以后有实际需求再复用 Spec 003，不另造删除协议。

## 5. Testing Decisions

只验证用户可见行为和公开接口，不绑定私有组件、内部状态机或模块组织。沿用[测试原则](../testing.md)，不引入新的通用测试接口或故障平台。

- **主要边界：实际手机 ↔ 真实后端 ↔ Web 的用户可见流程。** 在实际使用的系统选择/保存提供方上完成双向交换，并在同一组日常操作中检查多选串行、取消、结果未确认、系统保存及生命周期行为，不建设全平台矩阵。
- **复用边界：现有后端公开 HTTP 接口。** 复用既有文件传输、查询、下载及原生 Bearer 认证测试的隔离 SQLite 和临时文件目录。仅在实现改动相关行为时补针对性验证，不重复未受影响的容量、清理和认证故障矩阵。
- **必要的客户端补充。** 现有 Android 规则单元测试可作为纯规则验证的先例，但不按 ViewModel、队列或暂存组件逐层制定测试要求；仅在实际需要时补少量可观察行为测试，不新增测试平台。

保留 F01–F05 作为定位编号，不要求逐项独立测试或报告；本轮确认的行为合并到既有路径：

- F01：实际手机通过系统选择器与 Web 双向交换文件，多选、追加、自动串行发送和移除等待项可用；一个上传与一个下载可同时进行，不阻止独立文本发送。
- F02：文件过大、空间不足、源 URI 读取失败时明确报错，内存与暂存有界。
- F03：上传响应丢失不自动重传，手动查询原身份，暂停上传队列但不阻止下载；中断不报撤回，结束本轮提示重复风险；失败后重新选择为新发送。
- F04：取消位置选择不报错、不开始下载；区分下载中与保存中，支持取消，错误或未完成保存不报成功，保存失败/中断提示可能的残留；正常系统保存可由文件管理器打开，服务器删除不影响副本。
- F05：旋转不重复传输，后台不启动下一个文件任务、不主动暂停已开始任务的后续步骤；进程终止不自动重发；认证失效或退出中断未完成传输，重登不自动恢复；私有临时数据可清理，不误删完整本地副本。

复用已有适用证据，不把 APK 构建或后端测试通过当作真机验证通过，不承诺后台任务一定完成。旧 F01–F15 中的本地索引、并发调度和持久恢复要求已撤销，不重新展开旧验收清单。

## 6. Out of Scope

- 独立本地下载页、本地副本索引数据库、应用内副本打开管理或删除、长期 URI 授权、扫描手机文件系统。
- 持久上传/下载队列、下载等待队列、进程终止后的任务恢复、独立原子暂存额度账本。
- 后台可靠传输、前台服务、WorkManager、后台同步或系统通知。
- 目录上传、分片或断点续传、文件内容去重、同次上传的后继重传、服务端强保证停止。
- 系统分享入口、多服务器、独立 Android 服务器文件管理页。
- 跨文档提供方原子保存、自动恢复或撤回覆盖、应用内重名分配、系统文件管理功能重实现。
- 多版本/厂商/提供方验收矩阵、完整故障矩阵、通用测试平台、旧客户端兼容层。
