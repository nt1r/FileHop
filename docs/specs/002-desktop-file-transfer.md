# Spec 002：桌面文件传输与容量控制

状态：已确认。本文为桌面文件传输与容量控制的权威需求、技术契约与验收依据；实施与验收进度见[路线图](../roadmap.md#阶段-2桌面文件闭环)，确认不代表验收通过。

本文件为该切片的唯一 Spec；[实施主 Issue #33](https://github.com/nt1r/FileHop/issues/33) 跟踪实施、前置条件和验收证据，不复制或替代本文件。

关联：[产品基线](../product.md) · [路线图](../roadmap.md) · [Spec 001](001-desktop-text-loop.md)

## 1. 目标与边界

在 Spec 001 的 Chrome、同域 HTTPS、认证与消息历史基础上，交付多文件流式上传、普通附件下载、容量控制和上传失败处理。

桌面文件多选及队列替代原先“不支持批量选择”的约定，不改变 Spec 001 的文本单次发送限制。Android 的多文件交互由[已确认的 Spec 006](006-android-files.md) 定义：复用服务器上传协议，客户端增加 URI 暂存和进程内调度，不追溯增加桌面阶段的 Android 验收要求。

不包含：目录上传、在线预览、分片、断点续传、内容去重、病毒扫描、跨刷新队列恢复、可靠后台传输。已提交文件的列表管理与删除属于 Spec 003；本 Spec 只终止未提交上传，不删除已提交文件。

## 2. 已确认的用户行为

### 选择与队列

- 文件选择入口与页面内上传队列融入现有消息工作区，不另设传输页面；具体视觉布局在实现时细化。成功后通过消息流中的文件消息下载。
- 本切片提供文件选择入口，拖拽及粘贴上传不在本次范围。
- 可一次选择多个文件并继续追加选择，校验后自动上传，不额外点击发送。
- 每个文件独立展示名称、大小、进度、结果和停止操作，成功后产生一条文件消息。
- 单页面最多 3 个活动上传，其余等待自动接续；等待项不预留服务器空间，可单独移除。
- 文本发送独立可用；不采用全实例单活动上传限制。
- 页面内队列保留选择顺序；消息按服务器成功提交顺序排列，时间为服务器确认保存时间，不是本地文件修改时间。
- 数据传输达到 100% 后显示等待服务器确认，不提前报告成功。
- 明确失败的任务不阻塞其他任务，重试由用户触发，不自动循环上传。

### 允许的文件

- 单文件默认最大 100 MiB（104,857,600 字节），可配置；允许 0 字节文件。客户端通过认证的限制查询获取有效上限，不将默认值永久硬编码为服务器能力。
- 不按扩展名或 MIME 类型设白名单。MIME 仅为不可信元数据。
- 实体使用安全唯一标识保存，不以原始名称拼接路径，不执行上传内容。
- 下载为附件，不在应用同域内直接渲染 HTML、SVG 等上传内容。
- 不扫描病毒，不承诺用户上传文件的内容安全。

### 结果未知与重试

- 文件引用、发送标识和状态保存在当前页面内存；刷新或关闭不恢复文件选择、队列或上传进度。与服务器文件页之间的应用内切换遵循 [Spec 003 的导航生命周期](003-server-file-management.md#应用内导航刷新与状态校正)。
- 页面仍在时，同次重试保留原发送身份，先确认服务器结果；成功则返回原消息，不重复上传。
- 服务端确认仍在接收或处理中时，占用一个页面活动名额，不启动同次第二个写入。
- 服务端确认成功、失败或停止后释放页面活动名额；失败若需重试，必须从头传输。
- 断网而无法确认任务状态时，暂停启动新的上传；网络恢复后先协调未知任务，再继续等待项。
- 用户刷新后重新选择是新操作，应提醒先检查历史，避免重复。相同文件内容的新操作仍允许产生新消息。

### 停止

- 等待项可直接移除；活动上传可停止本页面继续发送文件数据，并请求服务端终止。
- 服务端确认尚未提交且终止成功，显示已停止；临时实体尚未清理则空间仍未释放。
- 已提交的上传返回成功，不能谎报取消，更不能自动删除已提交文件。
- 不能确认结果则显示结果未确认，可查询或放弃确认。放弃不是撤回，不自动重发。
- 丢弃任务视图不代表服务器资源已释放；服务端仍须按状态和超时协调清理。

### 登录到期和退出

- 已认证并开始的传输不因会话自然到期主动截断；新请求必须重新认证。
- 登录失效后暂停新上传，页面内保留队列和文件引用，隐藏文件名、进度等敏感内容。
- 同页重新登录后先协调已经开始的任务，自动继续尚未开始的等待项；不自动重发失败项。
- 从生产发布阶段起，队列恢复还须满足[Spec 004](004-web-production-deployment.md) 的 API 兼容检查。不兼容的旧页面不得自动启动新上传；已有任务通过最小稳定控制接口协调，不强制刷新丢弃文件引用。
- 自动继续仅针对选择时已经授权上传的文件，不改变 Spec 001 的文本草稿不自动发送规则。
- 主动退出停止本页面数据传输、清空等待队列及敏感状态，并尽力请求终止未提交上传。网络失败不承诺立即终止服务端任务，由服务端超时清理兜底。
- 已提交文件不因退出删除；迟到响应不得重新展示退出后已清理的敏感内容。

## 3. 容量与超时

容量控制随本切片交付；用量展示、用量查询接口与已提交文件的删除入口随 [Spec 003](003-server-file-management.md#容量) 的独立服务器文件页交付。上传区不展示容量面板，但须明确提示空间不足、清理未完成等影响当前操作的原因。仅完成本切片不代表包含空间管理的阶段 2 已完成。

- 文件额度默认 1 GiB（1,073,741,824 字节），不是整台 VPS 硬盘上限。
- 开始前按申报大小原子检查并预留完整额度；空间不足明确失败，不无限等待空间。
- 新的传输尝试在准入时使用当时有效的单文件上限与总额度；已获预留的尝试锁定其获准字节数，在不中断进程的配置调整中不被追溯作废。调低额度不删除文件，仍计入既有预留，拒绝会新增超额占用的申请。
- 若修改配置需要重启，未完成尝试仍按原有启动恢复规则终结；显式重试创建的新尝试重新校验新限制。配置快照不构成上传资格保证。
- 占用包括已提交文件、活动上传的完整预留、待清理的残留占用；同一临时文件包含在原预留内，不能双计费或漏计。
- 同次重试不重复预留，同一上传不能同时有两个写入者。
- 实际字节数必须等于申报值；超过则中止，不足不能提交。传输过程不能占用数据库长事务。
- 清理未完成的实体仍占额度，不提前释放；同一预留不能先释放再被旧请求继续写入。
- 即使额度足够，也检查磁盘可用空间并正确处理 ENOSPC 等写入失败。
- 准备完成后默认 2 分钟未开始传输，回收未使用预留。
- 传输中默认连续 2 分钟无文件数据则中止；单次最长 30 分钟。参数可配置。
- 清理失败后台重试，不把待清理占用当作已释放。
- 上传与下载独立配置连接、首响应、无进展及整体传输期限；文本/JSON 的 15 秒整体超时不得套用于文件体。上传遵循上述 2 分钟无数据/30 分钟整体期限；下载采用独立可调无进展策略，不要求在 15 秒内完成。具体客户端及 Caddy 参数在实现时配套记录、验证，持续进展的合法传输不得被控制请求短超时截断。
- 后端重启先协调遗留上传、文件和额度，再接收新上传；已提交消息读取仍可用。

## 4. 下载

- 从文件消息点击下载，交给 Chrome 下载管理器；未来 Spec 003 的列表复用同一下载能力。
- 每个新请求鉴权，不允许只凭文件 ID 或路径下载。
- 使用原始文件名的安全版本作为附件名称，浏览器决定同名文件如何保存。
- 服务器流式响应；不把整个文件读入内存，Web 也不要求先完整读取为 Blob 再保存。
- 不承诺 Range 续传、暂停恢复、在线预览或本地下载历史管理。
- 文件不可用、已删除或未认证时不返回文件内容；Web 处理能识别的请求错误，不承诺获知最终本地保存结果。
- 下载与删除并发遵循[已确认的 Spec 003](003-server-file-management.md)：服务端存在活动读取时拒绝删除，删除被接受后拒绝新读取，不通过删除强制终止既有下载；判定不跟踪浏览器最终落盘。

## 5. 已确认的技术契约

本节区分发送身份、传输尝试及实体提交，以支持完整重传而不引入续传。具体内部结构可调整，但必须满足并发、崩溃和取消语义。

### 发送身份与传输尝试

- 文件发送使用与文本发送共享身份空间的 `send_id`，固定类型、原始名称、申报大小、来源标签及声明 MIME。跨类型复用或不同元数据复用同一标识应拒绝。
- 每次从头传输有独立 `attempt_id`，由客户端在准备请求前生成并固定；一次发送可以有多个先后失败的传输尝试，但最多一个活动写入和一条成功消息。
- 首次准备与重试准备采用同一幂等契约：同一 attempt_id 的重复请求只返回原尝试状态，不新建预留、不复活已过期、失败或停止的尝试。用户明确重试才生成新 attempt_id，send_id 和文件元数据保持不变。
- 准备请求携带预期的前一 attempt_id（首次为空），服务端原子校验后创建后继尝试。已有后继时，旧请求不能再创建另一个后继；重放已存在的 attempt_id 则返回其原状态。
- 旧尝试失败后只有在写入者停止、临时数据清理完成且预留安全释放后，才能开始下一尝试。迟到的旧请求不得写入新尝试文件或提交消息。
- 页面内重试固定原 File 引用，不提供替换文件后继续使用原标识的入口。
- 本版不声明基于内容哈希的相同性保证：同标识成功重放返回原消息，不比较新的文件内容；它是操作幂等性而不是文件内容去重。第一次成功提交获胜。
- 相同元数据不能证明字节内容相同。若未来要求校验重选文件与原文件字节一致，应另行增加校验协议，不能默认为本版已具备。

### 接口职责

| 接口 | 职责 |
| --- | --- |
| `GET /api/transfer-limits` | 认证查询有效 max_file_size_bytes；仅提供能力快照，不预留额度 |
| `POST /api/file-sends` | 携带 send_id、首次 attempt_id 及固定元数据，幂等创建发送与首次尝试，原子申请预留 |
| `GET /api/file-sends/{send_id}` | 查询本次发送状态、活动尝试、清理状态及已成功消息 |
| `POST /api/file-sends/{send_id}/attempts` | 携带新的 attempt_id 及前一 attempt_id，幂等创建安全结束后的后继尝试；已成功则返回原消息 |
| `PUT /api/file-sends/{send_id}/attempts/{attempt_id}/content` | 流式上传原始字节，单写入者；完整接收并安全提交后返回成功 |
| `POST /api/file-sends/{send_id}/attempts/{attempt_id}/stop` | 幂等终止指定尝试，阻止其迟到准备/写入重新激活，不影响后继尝试；发送已提交则返回原成功结果 |
| `GET /api/files/{file_id}` | 认证附件下载 |

- 上传前的准备请求是客户端自动步骤，不增加用户点击。
- 先按 Spec 001 的共享认证矩阵检查应用凭证及适用的 Origin，再校验元数据、容量和写入资格，之后读取文件体；原生有效 Bearer 不强制 Web Origin。代理不得无界缓冲完整请求体。
- 同一 PUT 重复到达只允许一个取得写入资格，其他返回当前状态或冲突，不同时写文件。
- 准备请求结果未知时按 send_id 查询或幂等重试，不能另外生成发送身份。
- 停止请求先于对应准备请求到达时，持久记录该 send_id/attempt_id 的终止标记，不预留文件额度；迟到准备只返回该尝试已停止，不重新激活。此标记不应凭空确定未知文件元数据，也不终止其他 attempt_id。
- stop 和提交以服务端原子状态迁移决定先后：终止先取得提交裁决则禁止该尝试提交，提交先成功则返回原消息。清理须等待旧写入者退出；不能仅凭客户端 abort 判断结果。
- 停止后的显式重试使用新的 attempt_id；已存在发送继续使用原 send_id 和固定元数据。若首次准备未完成元数据登记，重试需补齐固定元数据并与终止标记协调，不能绕过后继尝试唯一性。
- 停止标记和已终结尝试身份首版不自动过期，以免旧请求重新激活；它们只保存必要控制元数据，准备及停止接口仍须受请求速率与资源约束。
- 所有应用接口鉴权，上传准备/传输/停止均遵循 Spec 001 共享认证矩阵，Web Cookie 同源防护不因原生支持而削弱。外层 Caddy 开发认证覆盖上传下载，但不能误套文本请求体上限。
- 认证分阶段交付：本切片实现并验收 Web Cookie 认证与 Origin 防护；本 Spec 中原生 Bearer 及相关混合凭证场景随 Spec 005 的原生认证能力交付后补验，不要求本切片提前实现原生凭证体系。
- 限制查询返回 max_file_size_bytes（非负整数）且不共享缓存；客户端进入传输界面或恢复会话后刷新，用于预检。离线或限制未知时暂停启动新的暂存/上传而非猜测可接受上限；服务端准入仍最终校验。

### 文件与数据库一致性

- 临时文件与正式文件位于同一文件系统，使用安全标识与排他创建，不覆盖其他文件。
- 接收结束校验字节数，完成文件持久化、移动到正式路径及必要的目录同步后，再以短事务提交文件元数据、消息和发送成功结果，并将预留转换为已提交占用。
- 文件系统与 SQLite 不是一个事务。提交期间需有可恢复状态记录；服务端只有确认完整文件存在且数据库提交成功才报告成功。
- 崩溃恢复以数据库成功提交记录为分界：无成功记录的活动尝试标记失败，不在恢复时补提交消息；其临时文件或已移动的未提交文件均作为残留清理，实际清理后才释放占用。即使字节已完整落盘，也可能需要用户从头重传。
- 数据库已有成功消息和文件记录：保留原消息及发送结果，重试不新建消息或文件；这覆盖消息提交后、响应前崩溃。
- 数据库已有成功记录但实体缺失或明显异常：保留历史和发送身份，下载返回明确的存储异常，不返回空文件、不改写为从未成功、不自动补发。此时不得仅因实体缺失就自动释放原占用，交由后续管理修复；不承诺检测无 Hash 校验的静默内容损坏。
- 删除未提交残留前确认没有旧写入者继续使用它；清理实体后再释放额度，禁止先释放再清理。
- 启动时协调暂存、正式孤立文件、预留及提交状态；后端单实例运行，不承诺多副本共同写本地存储。
- 已提交消息不得因一次响应失败而删除，元数据不可用也不能直接宣称上传从未成功。

### 上传名额与放弃确认

- 3 个名额属于页面调度限制，不是全实例只有 3 个上传的承诺；服务端仍设置可调资源上限和请求背压，过载明确拒绝而不无限排队。
- 服务端活动任务数、磁盘余量阈值及清理退避默认值在实现前按 VPS 资源选择并记录，不改变额度上限和用户语义。
- 放弃确认不再要求用户逐个处理该项，但页面保留最小状态协调记录，未确认活动任务仍计入名额。队列显示仍待确认的任务数量及等待原因，不把占用完全隐藏；不能借反复放弃绕过页面名额。
- 查询确认任务成功、失败或停止后自动释放页面名额；清理中的文件仍保留服务端容量占用，两者不是同一资源。网络恢复先协调未知任务，不因放弃而绕过暂停新上传的规则。
- 未能证明终止的任务继续查询或依靠服务端超时终结，放弃不自动重发。刷新会丢失页面记录，不承诺跨刷新或跨标签页维持全局最多 3 个任务；服务端资源上限和容量约束始终兜底。

### 附件安全与消息模型

- 下载使用 Content-Disposition: attachment、可靠编码的安全文件名及 X-Content-Type-Options: nosniff，默认 application/octet-stream；声明 MIME 仅用于元数据展示。
- 文件名去除路径分隔符、控制字符及危险头部字符，空结果使用安全默认名；数据库可保留原始展示名称但不得在头部或路径中直接拼接。
- 本阶段扩展 Spec 001 的消息结构为显式 TEXT/FILE 类型，FILE 包含 file_id、名称、大小、声明类型及服务器状态；文本字段只适用于 TEXT。公共字段 id、send_id、source_label、created_at 保持原语义，具体类型化字段在本阶段同步服务端及 Web 客户端。
- Spec 001 仍是独立的文本交付切片，不要求阶段 1 提前实现文件功能；类型化消息及共享查询扩展从 Spec 002 生效。
- 文件成功提交加入已有服务端消息顺序；增量与历史分页复用现有契约，旧的客户端未知类型处理应安全，不将 FILE 当作空文本。
- 现有 `GET /api/sends/{send_id}` 对文件发送成功返回同一消息；未提交上传详情由 file-sends 接口查询，不把“未找到成功结果”当作未开始。
- 从 Spec 003 文件管理阶段起，所有包含文件状态的响应携带 state_version，按其版本合并规则防止状态回退；成功发送重放返回原消息及当前文件状态，不重建已删除实体。此扩展不要求文件传输阶段提前实现完整管理与删除功能。

## 6. 验收场景

| 编号 | 场景与预期 |
| --- | --- |
| F01 | 多选并追加，自动开始，页面最多 3 个活动任务，等待项可移除，文本仍可发送 |
| F02 | 文件独立进度/停止/结果，数据到 100% 不提前显示成功，消息按提交顺序排列 |
| F03 | 空文件可上传；100 MiB 边界正确；超限拒绝；任意类型不被执行或内联展示 |
| F04 | 并发申请超过 1 GiB 时不能全部获准；等待项不预留，拒绝不无限等待空间 |
| F05 | 申报大小与实际字节不一致均不提交；文件流式读写，内存不随文件体积线性增长 |
| F06 | 准备/上传响应丢失、重复 PUT、重复提交及同标识不同元数据均不产生重复消息或并行写入 |
| F07 | 重试准备响应丢失、尝试过期后重放、重复后继创建均不新增意外尝试或预留；显式重试从头开始，旧写入不能影响新尝试 |
| F08 | 停止早于准备仍阻止该尝试激活；旧停止请求不影响新尝试；停止与提交有确定裁决，已提交不撤回，未知不谎报停止 |
| F09 | 断网暂停新任务，恢复先协调未知任务；放弃后显示占用原因、不绕过名额，确认终结后释放页面名额，待清理仍占服务器额度 |
| F10 | 凭证到期暂停等待项，不截断已认证传输；同页登录协调并继续等待项，不自动重发失败项 |
| F11 | 主动退出清空队列并尽力停止，迟到响应不泄露页面内容；刷新不恢复本地队列或自动重传 |
| F12 | 准备超时、无数据超时、总时限触发清理；清理失败不提前释放额度 |
| F13 | 各边界注入崩溃：文件已落盘但数据库未提交则失败清理，不补消息；数据库已提交则返回原成功结果；清理后才释放额度；已提交实体缺失返回存储异常而不重复创建消息 |
| F14 | 已提交后进程异常退出仍可下载；磁盘写入失败不报告成功；恢复前不接收新上传 |

需要真实 SQLite 与临时文件系统测试原子预留及崩溃边界；浏览器验证多文件调度、重新登录、停止、下载及 HTTPS 代理。测试可缩短时限，但生产默认值应被配置验证。

## 7. 确认与完成条件

整份 Spec 已最终确认，包含尝试创建幂等性、按尝试停止、数据库提交分界的恢复规则、放弃后的可见调度状态及阶段契约衔接。Spec 001 已同步阶段扩展说明，不追溯增加阶段 1 的文件验收要求。

本 Spec 当前阶段范围实现并通过上述适用验收后，文件传输切片完成；F17 的原生认证部分随 Spec 005 补验，不作为本阶段完成前置条件。服务器列表、实体删除及状态校正仍由 Spec 003 验收。
