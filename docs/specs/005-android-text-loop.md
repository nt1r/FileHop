# Spec 005：Android 认证与文本

状态：范围已确认，实施中；[实施主 Issue #99](https://github.com/nt1r/FileHop/issues/99) 跟踪实现与验证。Web 正式自用前置已完成；工具链与安装说明见 [Android 指南](../android.md)，构建通过不代表手机验收完成。

关联：[产品基线](../product.md) · [路线图](../roadmap.md) · [Spec 001](001-desktop-text-loop.md) · [Spec 004](004-web-production-deployment.md) · [Spec 006](006-android-files.md)。本文件是本切片唯一权威来源，实施 Issue 只引用范围和验证编号，不重复维护完整需求。

## 1. Problem Statement

桌面 Web 已能使用共享消息流交换文本，但用户尚不能通过自己的 Android 手机完成原生登录、发送、查看和复制。需要先交付日常可用的手机文本闭环，而不是提前建设完整移动平台或枚举罕见异常。

## 2. Solution

使用 Kotlin + Jetpack Compose 原生应用，在用户实际使用的手机上完成登录、与 Web 双向文本交换及复制。界面保持现代、美观，提供最近消息、加载更早、来源标签编辑和手动刷新；前台同步，后台暂停常规轮询。

首次配置一个 HTTPS 域名根地址，默认正式域名，确认后固定；更换需清除应用数据。通过 GitHub Release 签名 APK 手动安装和更新。首版最低版本按实际手机确定为 Android 16 / API 36，工具链见 [Android 指南](../android.md)；不承诺 Android 10 或多版本/厂商验收矩阵。

## 3. User Stories

1. 作为用户，我希望首次确认服务器地址后直接使用同一实例，以便不必每次重新配置。
2. 作为用户，我希望使用现有用户名和密码登录，以便手机和 Web 访问同一条私人消息流。
3. 作为用户，我希望有效登录在普通重启应用后仍可使用，以便不必反复输入密码。
4. 作为用户，我希望登录到期后重新登录，以便继续使用而不自动延长凭证有效期。
5. 作为用户，我希望退出当前手机登录，以便清除本机凭证和敏感内容而不影响其他登录。
6. 作为用户，我希望密码重置能撤销所有登录，以便沿用现有账户管理方式。
7. 作为用户，我希望从手机向 Web 发送纯文本，以便交换文字、URL、命令和代码片段。
8. 作为用户，我希望在手机看到 Web 发来的文本，以便双向使用同一消息流。
9. 作为用户，我希望正文保留原始换行和合法空格，以便复制后仍可使用。
10. 作为用户，我希望主动复制完整正文，以便不附带来源标签，也不被应用自动覆盖剪贴板。
11. 作为用户，我希望编辑来源标签，以便辨认发送来源，而不建立物理设备身份。
12. 作为用户，我希望查看最近消息并加载更早记录，以便使用已有历史。
13. 作为用户，我希望前台自动检查新增消息并可手动刷新，以便无需后台同步也能日常交换文本。
14. 作为用户，我希望网络故障有基本提示且不清空现有草稿，以便连接恢复后继续操作。
15. 作为用户，我希望未确认发送能查询或使用原发送标识手动重试，以便沿用既有文本规则而不自动重复发送。
16. 作为用户，我希望旋转屏幕不会丢失进程内草稿或重复发送，以便正常操作手机。
17. 作为用户，我希望尚不支持的文件消息仍能安全显示名称和提示，以便不阻塞文本历史加载。
18. 作为用户，我希望签名 APK 可以覆盖更新，以便手动安装新版本而不必卸载正式版。

## 4. Implementation Decisions

### 客户端和服务器地址

- Android 使用 Kotlin + Jetpack Compose；正式 application ID 和 namespace 统一为 `top.hammerbilly.filehop`，开发版 application ID 为 `top.hammerbilly.filehop.dev`，与正式版数据隔离。首版最低及目标版本为 Android 16 / API 36，仅验证实际手机；编译 SDK 可随稳定工具链升级，当前版本见 Android 指南，不据此提高最低版本或改变目标系统行为。构建在 GitHub 托管 x86-64 runner 上使用官方 SDK，不要求开发 VPS 安装第三方 ARM64 工具。
- 只配置一个 HTTPS 域名根地址，无 userinfo、其他路径、query 或 fragment。使用标准 URL 解析器，HTTPS 验证不可绕过。
- 凭证只发往配置的 origin；敏感请求不自动跟随重定向。
- 不提前锁死内部模块、状态机或 SDK 版本，先实现实际手机的正常使用路径。

### 认证与安全

- 使用独立随机 Bearer Token；服务器只保存摘要、原生会话类型及固定 12 小时到期时间，不采用刷新 Token，不保存密码。
- `POST/GET/DELETE /api/native/session` 分别登录、检查、撤销会话。原生登录使用 JSON `{ "username": "...", "password": "..." }`，成功返回 `{ "token": "...", "expires_at": 0, "server_time": 0 }`，两个时间为 Unix 秒。检查返回同样的时间字段但不重新返回 Token；撤销返回 `{ "state": "logged_out" }`，重复撤销同一合法格式 Token 可成功。原生接口不设置 Web Cookie，复用现有密码校验和节流。响应均 `Cache-Control: no-store`，检查/撤销只接受原生 Bearer，不把 Web Cookie 当作原生会话。
- 共享业务接口支持有效原生 Bearer；不能仅因没有 Origin 放行。Web Cookie 写入仍检查 Origin，混合 Cookie/Bearer 拒绝。密码重置撤销两类会话；普通服务重启不无故撤销有效登录。
- 持久 Token 使用平台受保护存储并排除备份；密钥失效要求重新登录。退出立即清除本机 Token 与敏感内存，服务器撤销失败如实提示。
- 冷启动检查会话；明确失效或已知到期时隐藏内容并重新登录。普通前台网络错误保留现有内容及草稿，不误报退出。
- 回到前台恢复读取即可，不强制每次联网解锁或遮挡内容。
- 不记录密码、Token 或正文；不自动读取/覆盖剪贴板。不把最近任务预览遮罩和跨版本截图差异作为首版门槛；使用系统默认行为，不承诺额外屏幕隐私锁。
- 原生开发先通过隔离本地后端测试；若需要真实开发 Basic Auth 入口，再实现局限于开发站点的 Token 头映射，不把它作为首个文本闭环前置。不能移除已有开发 Web 访问保护，不能把临时认证头作为生产后门。

### 文本与生命周期

- 复用 Spec 001 的正文校验、来源标签、发送标识、同次重试、结果未确认、分页及增量游标规则，不建立另一套后端协议。
- 单个文本发送在途时禁止重复点击；失败不自动换身份重发。未确认发送保留原身份供查询或用户重试，沿用 Spec 001 的放弃确认语义。
- 正文只留进程内存，不进日志或系统持久保存状态。旋转不重复发送、不丢进程内草稿；进程终止不承诺恢复草稿，不自动重发。
- 登录失效只保留进程内草稿及未确认发送上下文供重新登录后手动处理，不在未认证界面展示，不自动发送。
- 前台每 10 秒轮询，后台暂停，新请求出错退避；迟到响应不能在退出后恢复内容或清空新草稿。
- 遇到 FILE 消息时安全显示名称；文件功能尚未实现时只显示不支持提示，不阻塞历史加载。沿用已有文件状态版本，不自行推进消息游标。

### 安装更新

- GitHub 托管 runner 构建签名 APK，GitHub Release 手动安装。正式版保持稳定 application ID、签名和递增 versionCode。
- 签名密钥安全保管并保留独立副本，不进入 PR、缓存或日志。使用受信任提交和最小发布权限，不建设额外发布准入体系。
- Web/后端不兼容更新时由用户同步更新 APK；不承诺旧版可重新登录协调任务，不定义 API 兼容范围和稳定控制协议。更新前保存草稿、结束传输。

## 5. Testing Decisions

只验证用户可见行为和公开接口，不绑定私有组件、内部状态机或模块组织。沿用 [测试原则](../testing.md)，不为本切片引入新的通用测试接口或故障平台。

- **服务端公开 HTTP API 与管理命令**：复用现有认证、消息和文件集成测试的隔离 SQLite、临时文件目录及可控时间。补原生会话、共享认证路径和密码重置，保留 Web Origin 防护；不通过 Mock 替代存储正确性，也不重测未受影响的全部文本和文件规则。
- **实际手机与 Web 的可见路径**：以实际手机安装、登录、双向发送、复制和刷新为主要依据。旋转和必要网络失败反馈在同一路径验证；只在实际需要时补少量客户端测试，不建设系统版本矩阵。
- **签名 APK 覆盖更新**：确认正式签名可覆盖安装，并检查秘密、正文及备份排除。不把 APK 构建成功当作实际手机验证通过。

保留以下最小验证编号，作为定位而非逐项独立测试或报告要求：

- A01：用户实际手机安装、登录，与 Web 双向发送、复制，分页和前后台刷新可用。
- A02：Token 保护、到期、退出及重置密码有效；Web Origin 防护不因原生认证削弱。
- A03：旋转不重复发送；网络失败和文本发送响应丢失不自动重发，重新登录不自动发送草稿。
- A04：稳定签名的覆盖更新可用；日志、APK 和备份不包含真实秘密或正文。
- A05：补验 S002-F17、S003-M13 的原生接口认证，不要求提前完成 Android 文件界面。

已有适用证据直接复用，不重新展开旧 A01–A14 清单。其他系统版本及罕见生命周期问题按实际反馈处理。

## 6. Out of Scope

- Android 文件上传、下载和服务器文件管理界面，文件交换留给 Spec 006。
- 多服务器、离线消息库、持久草稿、进程终止后的发送恢复。
- 后台同步、通知、系统分享入口、WorkManager、前台服务、应用内自动更新。
- 多系统版本/厂商验收矩阵、额外屏幕隐私锁、旧客户端兼容层。
- 原生登录响应丢失的专项恢复协议、退出撤销失败后的凭证保留和重试机制。这些罕见异常不提前设计或建立专项测试，实际发生后再处理；现有基本错误反馈和安全约束不撤销。
- 为完整验收表、状态机或未来扩展提前拆实施子票和建设测试平台。
