# Spec 005：Android 认证与文本

状态：已确认，待实现。本文为 Android 认证与文本的权威需求、技术契约与验收依据；确认不代表已经实现。

关联：[产品基线](../product.md) · [路线图](../roadmap.md) · [Spec 001](001-desktop-text-loop.md) · [Spec 004](004-web-production-deployment.md)

本文件为该切片唯一 Spec，尚未创建远程 Issue。

## 1. 目标与范围

使用 Kotlin + Jetpack Compose 原生客户端完成 Android 与桌面 Web 的认证及文本交换，复用已有消息顺序、分页、发送标识和来源标签规则，不建设另一套消息后端。

最低 Android 10（API 29）；编译及目标 SDK 在实现时选用合适的稳定版本。至少验证最低支持版本和一个较新版本，不承诺覆盖所有厂商。

本阶段不含文件传输、本地下载管理、系统分享入口、后台同步/通知、持久化草稿、离线消息库、搜索、富文本、生物识别锁或应用内自动更新。文件消息可能已存在于服务器，如何安全展示见技术契约；不因文本阶段而删除或误读它们。

## 2. 已确认的用户行为

### 服务器配置

- 首次使用配置 HTTPS 域名根地址，默认 `https://transfer.hammerbilly.top`。首次配置确认前允许纠正输入；确认后固定，不提供应用内切换服务器入口。
- 不支持 HTTP、跳过证书验证、自签名信任绕过或子路径部署，不维护多服务器账户列表或同时登录多服务器。
- 退出及重新登录沿用原服务器。需要更换服务器时，通过系统清除应用数据后重新配置，并明确会删除凭证、配置及应用管理的本地副本；清除本机数据不等于撤销服务器会话。
- 此规则由 Spec 006 讨论修订此前的应用内服务器切换方案；不建设跨服务器本地文件归属或实例身份检测。
- 开发构建可配置开发域名，额外 Basic Auth 凭证不写入源码或 APK。

### 登录与持久凭证

- 用户名密码登录，独立可撤销凭证固定有效 12 小时，不自动续期、不保存密码。
- 凭证使用 Android Keystore 支持的方式保护后持久保存，重启检查原会话，到期时间不因重启延长。
- 凭证不参与系统自动备份或设备迁移；密钥不可用时清除凭证并要求重新登录。
- 会话失效或到达已知到期时间时隐藏消息与草稿，提供重新登录；重新登录不自动发送草稿。
- 冷启动或应用从后台恢复前台时，先检查会话，验证成功后才展示敏感历史与输入；验证期间显示检查状态。
- 检查遇到网络故障时保留受保护凭证及现有内存状态，显示连接失败和重试入口，不展示敏感正文、不误报凭证失效、不清空草稿。已知到期或明确失效时进入重新登录，暂停业务请求。
- App 已在前台且会话已验证时，普通网络故障不立即遮挡现有内容。旋转和普通界面重建不等于应用重新进入前台，不额外触发页面解锁。
- 主动退出确认后清除本机凭证、消息、草稿和发送状态；网络异常须说明服务器凭证可能尚未撤销。
- 服务端密码重置仍撤销所有 Web/Android 会话，不影响消息及发送身份。

### 生命周期与隐私

- 草稿、已加载历史及未确认发送只在进程内存中保存；旋转或普通界面重建、进程存活时短暂切后台、同页登录保留状态。
- 进程被杀、强制停止或冷启动不承诺恢复输入和发送身份；重新加载服务器历史，不自动重发。
- 不通过 SavedStateHandle、系统实例保存、持久数据库或自动备份间接保存正文与未确认发送载荷。
- 切后台停止常规定时轮询，不因为后台状态自动退出；不启动后台同步服务。
- Android 13（API 33）及以上使用 setRecentsScreenshotEnabled(false) 禁止系统为最近任务生成 Activity 截图，保留用户主动截图能力。
- Android 10–12 保留主动截图能力，不保证完全隐藏最近任务预览；如采用退出前遮罩，仅作为尽力措施，不作为安全保证。不以 FLAG_SECURE 静默替代并禁止用户截图。
- 上述版本差异必须在隐私说明及验收中明确，不能宣称所有支持版本都具备相同的最近任务保护。
- 不记录正文、密码、Token、开发 Basic Auth；不监控或自动覆盖系统剪贴板。

### 输入、历史与来源标签

- 多行输入，软键盘 Enter 换行，提供发送按钮；可支持外接 Ctrl+Enter，不作为手机核心操作前提，输入法组合输入不得误发。
- 单界面最多一个进行中或结果未确认的文本发送，不做队列。
- 复用 Spec 001 的纯空白集合、UTF-8 65,536 字节上限、合法正文原样保留、来源标签长度规则及服务端校验。
- 最近 50 条，点击加载更早记录；顺序由服务器决定，阅读旧消息不抢滚动，提供回到最新入口。
- 复制完整正文，失败不谎报成功；系统版本支持时将剪贴内容标为敏感，不能承诺消除系统或其他有权应用的所有访问。
- 默认来源标签 `Android`，可修改并本机保存，不采集硬件指纹；发起发送时固定标签，不改变历史。
- 前台每 10 秒获取新增消息，进入前台及手动刷新触发刷新；网络错误退避，遵守 Retry-After，不把失败游标推进。
- 同次重试使用原 send_id、正文和标签；结果未知不自动作为新操作重发。放弃确认保留为可编辑草稿并提示可能重复，旧响应不得清空新草稿。

### 安装与更新

- GitHub Release 提供签名 APK，用户手动安装/更新；不要求应用商店和 App 内自动更新。
- 全部检查与构建使用 GitHub 托管 runner，缓存 Gradle 依赖；正式签名凭证不进 Git、缓存、日志或公开制品。
- 正式应用保持稳定 application ID 和签名，开发版使用不同 application ID，与正式版数据隔离且可共存。
- Android 版本可独立于后端，声明支持的 API 兼容范围。不兼容时暂停新业务并提示更新，不自动丢弃内存状态；进程被系统终止的边界仍然适用。

## 3. 已确认的技术契约

### 原生认证与 Web 的隔离

- 原生使用随机高熵不透明 Bearer Token，SQLite 只保存摘要、固定到期时间和原生会话类型，不采用刷新 Token。
- 增加 `POST /api/native/session`、`GET /api/native/session`、`DELETE /api/native/session`，分别登录、检查、撤销当前原生会话；登录响应禁止缓存。
- 原生登录仅接受 JSON，不设置 Web Cookie，也不接受 Cookie 作为原生会话凭证；复用用户名密码校验、失败节流及全局哈希并发限制。
- 共享消息接口支持受控原生 Bearer 或 Web Cookie，两种认证路径明确区分；同时提供两者则拒绝歧义请求，不在一个失败后静默回退另一个。
- Web Cookie 写请求继续执行精确 Origin 检查。原生 Bearer 请求可无 Origin，但必须是有效原生凭证；不能仅凭 User-Agent 或缺少 Origin 跳过认证/CSRF 防护。
- 原生登录的跨域浏览器访问不开放 CORS，不允许表单 Content-Type 绕过 JSON 约束。无 Origin 是原生兼容要求，不是可信身份的证明。
- 原生 API 请求默认不自动跟随任何 HTTP 重定向，包括同源重定向；遇到 3xx 提示检查服务器地址或入口配置。登录请求体中的密码、Bearer Token、开发 Basic Auth 及临时 Token 头均适用，不仅依赖网络库自动移除 Authorization。
- 服务器地址仅接受 HTTPS 域名根地址，路径可为空或 `/`，拒绝 userinfo、query、fragment、其他路径和 IP 字面量。允许合法显式端口（1–65535），未指定时为 443；这不改变本项目 VPS 仅开放公网 TCP 443 的部署约束。
- 使用标准 URL 解析器规范化 IDN/主机名大小写及默认端口，以 scheme、规范化主机、有效端口组成精确 origin。凭证及开发入口配置绑定首次确认的 origin，不能向其他 origin 发送；规范化不能把不同端口视为同一服务器。
- 登录超时后由于 Token 响应可能丢失，可能留下一个无法使用的会话，允许自然过期，不声称像 Cookie 那样可无凭证找回登录结果；重试仍受节流，不无限自动登录。

### 开发入口的 Basic Auth 冲突

- Spec 004 的开发 Basic Auth 与原生 Bearer 都占用 Authorization，不能同时塞入一个头，也不能因 Caddy 移除外层头而丢失原生凭证。
- 仅开发构建使用单独的临时原生凭证头承载 Token，Authorization 留给外层 Basic Auth。Caddy 先验证 Basic，再删除它，将开发专用 Token 头映射为标准 Authorization: Bearer 并移除该临时头。
- 映射只在开发站点生效，生产拒绝该临时头；后端不为此新增通用认证后门。无外层认证请求不能靠注入临时头绕过 Caddy。
- 外层凭证仅在开发构建运行时输入并受保护保存，不借用正式应用密码，不因 App 退出误称浏览器或其他客户端的外层认证已撤销。
- 外层拒绝沿用 Web 已有的可识别入口错误标记，不能把所有 401 都当作应用 Token 失效。只有受识别的应用认证错误或已知到期才能触发应用重新登录；外层认证失败提示检查开发访问凭证，未知格式响应提示入口/协议错误。
- 外层故障暂停请求，保留原 Token、草稿和发送身份。修复外层凭证后重新检查应用会话，再恢复业务，不自动重发结果未知的写请求。
- Caddy 先验证外层认证再删除其 Authorization；仅当开发临时 Token 头存在且格式有效时映射。没有该头时不生成空 Bearer，不破坏开发 Web Cookie 流程。拒绝重复或歧义认证头，不在映射失败后静默降级认证。
- 临时头须在受信任边界消耗并移除；生产入口/后端拒绝它，不允许其绕过 Bearer 或 Cookie 校验。所有入口及 HTTP 客户端调试日志均需脱敏这些头。
- 具体头名和 Caddy 映射语法由实现验证后固定；真实开发 Web 与 Android 请求都须通过验证，未验证前不宣称可用。

### 状态与网络生命周期

- 进程内共享状态持有草稿及发送尝试，ViewModel 跨配置重建；UI 不直接持有唯一的网络操作身份。正文和未确认发送载荷不得进入 rememberSaveable、SavedStateHandle 或其他可被系统序列化的保存机制。
- 前后台判断使用应用级生命周期，区分旋转重建与真正后台恢复；从后台恢复时同步进入受保护的检查界面，旧请求或旧会话检查响应不能提前解锁。
- 新认证周期开始时，检查成功结果只对对应周期及固定 origin 生效。检查失败保留重试入口和内存状态，服务器不可达不能自动延长已知过期时间。
- 已发出的文本写请求不因旋转重新发起；切后台不承诺继续完成，也不把生命周期取消等同于服务端取消。回前台先校正结果，再允许重试。
- 认证周期变化递增本地请求代次，旧响应不得恢复已隐藏的敏感页面或覆盖当前状态；不支持运行时切换服务器。
- 登录到期按服务端 expires_at 判断并考虑时间偏差；本地预判只用于锁定界面，权限以服务器为准，不延长会话。
- 共享消息解析遵循 TEXT/FILE 类型。文件阶段未实现时，FILE 安全展示名称及“本版本暂不支持文件操作”，不当作空文本、不阻塞分页、不提供无实现的下载/删除按钮。
- 文件状态版本只影响文件记录，不推进消息增量游标。读取新消息、发送响应与历史分页去重/游标规则复用 Spec 001–003。
- 退出时先清除可恢复的本机凭证和敏感状态，撤销网络操作仅短暂持有必要 Token，完成或超时后释放；失败告知用户服务端会话可能持续至到期，可用服务端重置密码撤销全部会话。
- 与 Web 不同，本机持久 Token 可由 App 主动删除，因此本地退出后重启不得用旧 Token 自动登录，不把 Web HttpOnly Cookie 的限制照搬到 Android。

### 更新与发布

- 正式构建以独立 Android 版本 tag/命名空间触发（例如 android-vX.Y.Z），服务端 vX.Y.Z 发布不默认强制同时构建 APK。
- 复用 Spec 004 的可信发布准入和确切 SHA 检查，Android tag 同样来源于 main 正式提交序列；PR 与普通测试任务无正式签名权限。
- versionCode 单调递增，签名在独立受控发布步骤执行，记录签名证书指纹、APK 校验和、Git SHA、versionName、最低系统版本及 API 兼容范围。
- 非兼容服务器保留 Spec 004 的稳定版本查询、登录/会话检查、已有任务查询/终止/退出；会话到期仍可重新认证以协调旧任务，但认证成功不解除 API 不兼容限制，不发起新业务；APK 手动更新可能导致进程终止，更新提示不得承诺保留纯内存草稿。
- 不要求服务器备份恢复，但正式 APK 签名密钥需要由操作者安全保管和保留独立安全副本；丢失可能导致无法按原签名覆盖更新。

## 4. 开工前明确及验证事项

- 在 API 29 和 API 33 及以上分别验证最近任务行为，按已明确的平台差异记录证据，不将旧版遮罩当作严格安全保证。官方依据：[Activity.setRecentsScreenshotEnabled](https://developer.android.com/reference/android/app/Activity#setRecentsScreenshotEnabled(boolean))，该 API 自 33 引入，区别于同时限制截图的 FLAG_SECURE。
- 最终 application ID、SDK/工具链版本、Token 保护及备份排除方式、APK 签名流程在实施配置中确定。服务器地址规则按本 Spec 执行。
- 开发 Basic Auth 与原生认证头映射、受保护存储失效、厂商进程回收及真实 Chrome ↔ Android 交互需实测。
- 不默认 GitHub runner 的模拟器架构或硬件加速可用；测试 runner 根据 Android 工具链需求选择，不因生产 ARM64 而强行复用后端构建架构。

## 6. 确认与完成条件

审阅修订已明确 Android 10–12 与 13+ 的最近任务隐私差异、所有敏感 API 请求的重定向禁用与地址规则、开发入口和应用认证错误分层、前台恢复的验证门槛。整份 Spec 已最终确认，包含这些可观察行为调整。

Spec 001/004 已同步原生认证与开发入口阶段扩展说明，不追溯扩大 Web 阶段验收。

实现及上述验收通过后完成 Android 文本切片，文件传输和本地下载由[已确认的 Spec 006](006-android-files.md) 交付。

从文件阶段起，FILE 消息占位替换为实际文件操作，增加上传队列、受限并发下载及持久的本地副本索引；它们不改变本 Spec 的文本单次发送限制，也不允许持久化文本草稿或远程消息历史。回前台验证、认证代次隔离及隐私规则继续适用，不追溯增加文本阶段的文件验收要求。
