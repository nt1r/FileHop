## 1. 最小目标

Kotlin + Jetpack Compose 原生应用，在用户实际使用的手机上完成登录、与 Web 双向文本交换及复制。SDK 和最低版本在开工时按实际手机确定，不承诺 Android 10 或多版本/厂商验收矩阵。

首次配置一个 HTTPS 域名根地址，确认后固定；更换需清除应用数据。开发版使用独立 application ID。无多服务器、离线消息库、后台同步、通知、系统分享入口或应用内自动更新。

## 2. 认证与安全

- 使用独立随机 Bearer Token；服务器只保存摘要、原生会话类型及固定 12 小时到期时间，不采用刷新 Token，不保存密码。
- `POST/GET/DELETE /api/native/session` 分别登录、检查、撤销会话。原生登录使用 JSON，不设置 Web Cookie，复用现有密码校验和节流。
- 共享业务接口支持有效原生 Bearer；不能仅因没有 Origin 放行。Web Cookie 写入仍检查 Origin，混合 Cookie/Bearer 拒绝。密码重置撤销两类会话。
- 持久 Token 使用平台受保护存储并排除备份；密钥失效要求重新登录。退出立即清除本机 Token 与敏感内存，服务器撤销失败如实提示。
- 冷启动检查会话；明确失效或已知到期时隐藏内容并重新登录。普通前台网络错误保留现有内容及草稿，不误报退出。
- 回到前台恢复读取即可，不强制每次联网解锁或遮挡内容。旋转不重复发送、不丢进程内草稿；进程终止不承诺恢复草稿，不自动重发。
- 不记录密码、Token 或正文；不自动读取/覆盖剪贴板。不把最近任务预览遮罩和跨版本截图差异作为首版门槛；使用系统默认行为，不承诺额外屏幕隐私锁。
- HTTPS 验证不可绕过；服务器地址只接受域名根地址，无 userinfo、其他路径、query 或 fragment。使用标准 URL 解析器，凭证只发往配置的 origin；敏感请求不自动跟随重定向。
- 原生开发先通过隔离本地后端测试；若需要真实开发 Basic Auth 入口，再实现局限于开发站点的 Token 头映射，不把它作为首个文本闭环前置。不能移除已有开发 Web 访问保护，不能把临时认证头作为生产后门。

## 3. 文本与生命周期

复用 Spec 001 的正文校验、来源标签、send_id、同次重试、结果未知、分页及增量游标规则，不建立另一套后端协议。单个文本发送在途时禁止重复点击；失败不自动换身份重发。正文只留进程内存，不进日志或系统持久保存状态。

最近消息、加载更早、主动复制、来源标签和手动刷新即可。前台每 10 秒轮询，后台暂停，新请求出错退避；未确认发送保留原身份供查询或用户重试。迟到响应不能在退出后恢复内容或清空新草稿。

遇到 FILE 消息时安全显示名称；文件功能尚未实现时只显示不支持提示，不阻塞历史加载。沿用已有文件状态版本，不自行推进消息游标。

## 4. 安装更新

GitHub 托管 runner 构建签名 APK，GitHub Release 手动安装。稳定 application ID、签名和递增 versionCode；签名密钥安全保管并保留独立副本，不进入 PR、缓存或日志。使用受信任提交和最小发布权限，不建设额外发布准入体系。

Web/后端不兼容更新时由用户同步更新 APK；不承诺旧版可重新登录协调任务，不定义 API 兼容范围和稳定控制协议。更新前保存草稿、结束传输。

## 5. 最小验证

- A01：用户实际手机安装、登录，与 Web 双向发送、复制，分页和前后台刷新可用。
- A02：Token 保护、到期、退出及重置密码有效；Web Origin 防护不因原生认证削弱。
- A03：旋转不重复发送；网络失败和响应丢失不自动重发，重新登录不自动发送草稿。
- A04：稳定签名的覆盖更新可用；日志、APK 和备份不包含真实秘密或正文。
- A05：补验 S002-F17、S003-M13 的原生接口认证，不要求提前完成 Android 文件界面。

旧 A01–A14 已收缩为以上检查，不要求逐项补历史清单。优先沿用服务端集成测试，仅补客户端状态和实际手机的核心路径；其他系统版本及罕见生命周期问题按实际反馈处理。
