# Spec 004：Web 生产部署与发布

状态：按单人自用范围简化。PR #86/#87 已合入远端 dev 的生产运行基础、独立迁移及内部就绪能力应复用；正式发布和手动更新待实现，隔离测试不代表生产已部署。

本文件是唯一权威 Spec；[主 Issue #74](https://github.com/nt1r/FileHop/issues/74) 跟踪实施。关联：[产品基线](../product.md) · [路线图](../roadmap.md) · [测试原则](../testing.md)。

## 1. 目标与非目标

把现有桌面文本、文件和删除能力部署到正式 HTTPS 入口，能安全地手动更新即可。接受停机和人工排障，不建设通用发布平台。

不要求：零停机、自动回滚、部署阶段恢复框架、部署工具兼容协议、候选发布源、独立发布准入 workflow、旧客户端兼容范围及稳定控制协议、备份恢复或 Android 提前交付。

## 2. 生产能运行

- 保留 Rust、SQLite、本地文件、Compose、Caddy 的现有方案。Caddy 提供构建后的静态页面和同域 API；生产不运行 Vite。
- Caddy 对已知前端页面 `/`、`/login`、`/files` 返回 `index.html`，支持直接打开和刷新；`/api/*` 仍转发后端。未知页面及丢失的静态资源返回 404，不将 HTML 冒充脚本；前端应用内未知路径展示页面不存在。
- 开发和生产使用独立项目、网络、账户、配置及绝对数据挂载。后端不直接暴露公网；Caddy 不读取数据库或上传目录。
- 容器路径保持 `/data/database/transfer.db`、`/data/files`，后端端口保持 8080。显式初始化，不因错误挂载或缺失数据库自动建替代实例。
- 共享入口仅通过公网 TCP 443 提供 HTTPS；证书自动管理使用兼容的验证方式，证书数据持久保存，不要求 HTTP 跳转。
- 生产不继承开发 Basic Auth；开发访问保护不因生产更新而消失。共享入口、网络及外部设置变更须单独授权，保留既有管理入口。
- 保留日志轮转、重启策略及简单的内部就绪检查。就绪须确认存储可用、上传恢复完成；不泄露内部路径。不把 Docker unhealthy 当作自动重启能力。

## 3. 构建与发布

- 沿用已有个人分支 → dev → main 流程及保护，不为本次简化重新调整远端设置。公开代码和产物前按 CONTRIBUTING 检查隐私、Apache-2.0 及必要第三方声明。
- GitHub 托管 runner 为确定的 main 提交构建 ARM64 后端镜像和前端静态产物；不在生产 VPS 跑 CI。版本 tag 使用 `vMAJOR.MINOR.PATCH`，验证来自本仓库且提交属于受保护 main，不要求 first-parent 发布序列。
- 使用一个发布 workflow 即可；限制 tag 创建/修改权限，不可信 PR 无发布或签名凭证，不用 `pull_request_target` 执行 PR 代码。发布 job 使用最小权限，构建产物不作为可执行的发布脚本。
- 记录版本、Git SHA 和产物 digest／校验和，前后端来自同一提交。仅在所需产物完整且检查通过后发布 Release；不覆盖已完成的版本。GHCR 制品公开后验证匿名拉取。
- 不再维护清单格式协商、部署工具兼容范围或重复迁移清单；SQLx 内嵌迁移及 checksum 是数据库升级依据。
- 发布检查针对目标提交及产物，包含隔离启动和必要升级冒烟；不要求另造候选发布体系或重复做全部人工验收。缓存只用于加速，不放秘密或用户数据。
- Actions 不持有 VPS 部署凭证、不主动连接服务器；操作者拉取受信任的发布产物。

## 4. 手动更新

一个小脚本配合运行说明即可，不建设可恢复的部署执行引擎：

1. 操作者保存草稿、停止新操作并等待传输结束。明确提示刷新或更新可能丢失内存队列。
2. 校验版本参数、产物来源、架构与 digest；使用明确的生产配置、项目名及绝对路径，不从当前开发目录推导挂载。使用本机锁避免两个更新命令并发。
3. 下载完成后停旧后端；确认没有其他进程写同一实例，再用目标镜像执行独立迁移命令。首次安装才使用初始化命令。
4. 启动同版后端及前端资源，检查内部就绪并执行简短冒烟；通过后报告完成，记录当前版本。
5. 迁移或启动失败则停止后续步骤、保留数据和日志，人工诊断。不自动清库、不盲目重试、不自动回滚，不恢复旧后端写新结构。

更新期间允许站点暂不可用或返回 503。简单静态维护提示是可选体验，不要求修改共享 Caddy 来实现持久维护状态机。必须避免新旧后端同时写数据；不能把进程启动当作更新成功。前端文件完整提取后再切换，不暴露半套资源。

更新后操作者刷新 Web，必要时手动更新 APK；不承诺不兼容旧客户端继续使用、重新登录协调旧任务或保留上传队列。未来需要版本提示时只做简单版本不匹配提示，不建设兼容范围或稳定控制层。服务端认证、输入校验及已有发送幂等仍生效，客户端不能将断连或 5xx 当作已确定未保存。

提供初始化、启动、版本查询、日志、重置密码、更新和失败排障说明；说明明文存储、无恢复承诺及不作为唯一备份。

## 5. 验证与完成

沿用现有隔离 SQLite、文件目录、Compose/Caddy 和少量真实后端浏览器检查。已证明且未受改动影响的行为直接引用既有证据，不逐条复演 Spec 001–003。

| 编号 | 必要验证 |
| --- | --- |
| D01 | 正式 HTTPS 可登录、交换文本、上传下载及删除；开发入口未受影响，内部服务无直接公网入口 |
| D02 | 生产配置与开发数据隔离；初始化及保留挂载的重建后消息、文件仍在，缺失挂载不创建替代实例 |
| D03 | 发布绑定确定 main 提交和完整产物，来源/权限正确，无运行秘密；目标 ARM64 产物可启动 |
| D04 | 手动更新停止旧写入者，目标镜像升级后保留合成旧数据；失败不清库或继续错误上线 |
| D05 | 版本、日志和运行说明可用；用户更新后刷新页面并走一次日常核心路径 |

本次简化重新定义 D01–D05；旧 D01–D16 引用只作历史证据，不继续作为新任务门槛。真实生产仅执行已授权的非破坏性检查。故障和迁移验证使用一次性合成数据；HTTPS、证书配置及挂载首次接入时检查，不把初次签发称为实测到期续签。

上述路径可自用且未发现安全或数据正确性阻塞，即完成本切片；不为视觉细节、罕见操作组合或重复验收记录拖延交付。
