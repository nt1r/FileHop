# Spec 003：服务器文件管理与删除

状态：已确认，待实现。本文为服务器文件管理与删除的权威需求、技术契约与验收依据；确认不代表已经实现。

本文件为该切片的唯一 Spec；[实施主 Issue #52](https://github.com/nt1r/FileHop/issues/52) 跟踪实施、依赖和验收证据，不复制或替代本文件。

关联：[产品基线](../product.md) · [路线图](../roadmap.md) · [Spec 002](002-desktop-file-transfer.md)

## 1. 目标与范围

为桌面 Web 提供服务器文件列表、空间用量、认证下载入口和单个实体删除，复用 Spec 002 的文件身份、存储及额度规则。

不管理 VPS 任意目录或客户端本地副本，不提供重命名、移动、排序选项、搜索、筛选、批量删除、回收站、恢复、定期全盘扫描或内容校验。Android 界面由[已确认的 Spec 006](006-android-files.md) 定义，共享本 Spec 的服务端契约；本地副本删除使用独立规则，不复用服务器活动下载锁或容量记账。

## 2. 已确认的行为

### 文件列表

- 独立“服务器文件”页，展示名称、大小、上传时间、来源标签及状态。
- 按成功提交顺序从新到旧，每批 50 条，点击加载更多，不提供自选排序。
- 展示可用、删除处理中、存储异常的已提交文件；未提交上传留在上传任务界面，不伪装成可用文件。
- 实体删除完成后从管理列表移除，文件消息仍保留并显示“服务器文件已删除”。
- 支持下载、单个删除及手动刷新。

### 删除入口与确认

- 文件列表和文件消息均可发起删除，复用相同行为。
- 确认框说明将删除服务器上的指定文件，所有设备不能再下载，本地副本不受影响，操作不可恢复。
- 发送删除请求后先显示请求处理中，不能在服务端接受前宣称正在删除。
- 文件正在下载时拒绝删除，提示下载结束后重试；不进入删除中、不排队、不在下载结束后自动删除。
- 删除被接受后立即禁止新下载；实体清理完成前显示“删除处理中，空间尚未释放”。
- 请求结果未知时提示并自动查询状态，不自动重发 DELETE，不把网络错误当作拒绝或完成，也不擅自恢复下载按钮。
- 收到 FILE_IN_USE 后结束本次删除流程，下载结束后须由用户再次主动确认删除。结果未知且查询仍为可用时，不能证明原请求不会迟到执行；页面保留未确认提示，仅允许用户明确确认后重试删除，不宣称重试是取消原请求。
- 重复删除安全，不重复释放额度。清理失败自动重试，不恢复文件可用状态。
- 实体清理完成并更新记账后，才报告删除完成、释放额度；永久保留文件消息、发送标识及必要元数据。

### 容量

- 用量集中展示在独立服务器文件页，随本 Spec 的列表和删除能力一起交付；消息工作区的上传区仅反馈当前操作相关错误，不展示容量面板。
- 显示应用总文件额度、已保存文件占用、上传预留、待清理占用，三项互不重复。
- 已保存文件：尚未进入删除流程的已提交文件，包括保守记账的存储异常文件。
- 上传预留：活动上传申请的完整大小，包含其临时数据，不再重复计算临时文件大小。
- 待清理占用：已接受删除的文件及失败上传残留尚未释放的额度。活动尝试终结时把原预留转换到该类别，不同时计入两类。
- 可用额度为总额度减上述占用之和，最小显示为 0；若因配置调低而超额，应明确提示，不自动删文件。
- 界面标为“应用文件额度”，不冒充 VPS 磁盘用量；实际磁盘不足单独提示。
- 用量是快照，上传资格以服务端原子检查为准。

### 应用内导航、刷新与状态校正

- 消息工作区与服务器文件页属于同一应用页面生命周期。两者之间切换保留文本草稿、上传队列、未确认发送及删除状态；返回消息工作区时恢复原状态。
- 应用内切页不停止上传或队列调度；浏览器仍在前台且认证有效时，已开始上传继续，等待项按 Spec 002 接续。浏览器隐藏、认证失效、主动退出以及刷新或关闭页面仍遵循 Spec 001、002 的生命周期规则；切页不等于刷新或关闭页面。
- 进入服务器文件页或手动刷新时更新列表和容量。
- 当前页面发起删除后，短周期查询相关文件删除进度，完成后更新已加载的对应消息及容量。
- 页面隐藏或认证失效时暂停查询，恢复可访问状态后刷新。
- 其他客户端在手动刷新或重新进入列表时校正已加载文件记录，不承诺实时删除同步。
- 消息流的 10 秒新增轮询不要求每次检查全部旧文件；新下载始终检查服务器实际状态。

### 存储异常

- 下载打开文件、删除清理或既有启动恢复过程中发现已成功记录的实体缺失或明显异常时，记录并显示“存储异常”，禁用下载，不谎报未曾上传成功。
- 列表与状态查询默认展示数据库中已知状态，不逐个检查实体，也不承诺即时发现外部文件变动；文件可能在点击下载后才被发现异常。
- 存储根目录不可访问等全局故障返回存储不可用，不能将所有文件逐条判为缺失。删除中的文件发生清理错误时保留删除中，不退回可用或存储异常状态。
- 允许通过相同确认流程删除，不提供恢复、重新绑定或重新上传修复。
- 缺失实体只有在确认受管存储位置可正常访问后，才可视为已无实体需要清理；权限错误、挂载异常、I/O 错误不能当作不存在。
- 处理完成后历史显示已删除并释放记账额度；诊断在服务端日志，页面不泄露内部路径。
- 不承诺发现无内容 Hash 校验的静默损坏。

## 3. 已确认的技术契约

### 活动下载的定义与作用域

- “正在下载”定义为服务端已授权并打开该文件、且仍持有读取句柄的下载请求。作用域为整个实例，不仅是发起删除的那个页面或设备。
- 浏览器不能可靠告知最终落盘时间，因此不以 Chrome 下载列表是否仍显示任务作为服务器判定依据；服务端关闭读取句柄即结束该次活动读取。
- 此定义保护尚在读取服务器实体的下载，不承诺跟踪代理缓冲或客户端落盘阶段。服务端关闭读取句柄后，即使 Chrome 仍在接收已读出的缓冲数据或落盘，也可以接受删除；不承诺浏览器任务显示结束前一律禁止删除。已下载本地副本始终不在删除范围。
- 复用 Spec 002 的单后端实例边界；活动读取计数不需要分布式锁，也不需要由客户端上报。

### 下载与删除的原子裁决

- 同一文件使用受控的准入协调：下载检查可用状态、取得读取资格并打开文件，与删除检查活动读取及持久标记删除中互斥。
- 下载先取得资格：删除返回明确的 `FILE_IN_USE` 冲突，不改变文件状态或容量。
- 删除先持久接受：后来的下载拒绝，不能在检查通过后绕过删除状态再打开文件。
- 不能仅靠“先查活动数，随后单独改状态”这种有时间窗口的流程。
- 已取得下载资格的请求在响应结束、连接断开、出错或取消时可靠关闭文件并减少计数；元数据探测 HEAD 不算长时间活动下载。
- 慢下载可能暂时阻止删除，不提供强制删除。读取的无进展超时和资源上限由实现配置并验证，不能无限泄漏句柄。
- 进程退出会关闭本进程的句柄；重启不恢复虚假的活动计数，但需确保没有另一个后端实例同时服务同一数据目录。

### 删除状态与恢复

- 文件状态至少区分可用、存储异常、删除处理中、已删除；活动下载是临时读取状态，不必持久建成业务文件状态。
- 短事务持久标记删除中并将占用从已保存转为待清理，总占用不变；事务提交后方可向客户端报告接受。
- 清理操作只能访问基于受管标识解析出的路径，不能使用客户端传入的路径。
- 实体删除及必要持久化完成后，再以事务标记已删除并释放占用；以状态条件更新保证只释放一次。
- 标记删除中后崩溃：重启继续清理；实体已删除但最终事务未提交：核实存储健康与实体缺失后完成记账，不能重复扣减。
- 清理失败保留删除中并退避重试，进程重启后继续。异常长期存在时在页面显示尚未清理完成，日志包含可定位的文件标识。
- 存储健康检查至少验证数据目录/挂载身份与可访问性；不得因挂载消失后出现空目录而将所有文件视为已清理。
- 上传成功结果不因删除失效。同 send_id 重放返回原消息及当前文件状态，不能重建被删除文件。
- 每个文件持久保存单调递增的 state_version；影响文件可用性及界面状态的变化与版本递增在同一事务内完成。失败清理的内部重试次数不必每次递增。
- `state_version` 在 JSON 中使用正整数十进制字符串，避免 JavaScript 整数精度损失；成功提交时从 `"1"` 开始，文本消息不带该字段。文件状态使用 `available`、`storage_error`、`deleting`、`deleted`。
- 消息列表、文件列表、发送结果查询、单文件及批量状态响应中的文件状态均携带该版本。迟到异常检测使用状态条件更新，不能把已进入删除中或已删除的记录改回存储异常。
- 普通查询不主动扫描磁盘；按需检测到的单文件异常持久记录。存储健康不确定时保留原记账并返回安全错误，不能以 ENOENT 以外的错误假装实体缺失。

### 接口职责

| 接口 | 职责 |
| --- | --- |
| `GET /api/files` | 新到旧分页列出尚未完成删除的已提交文件 |
| `GET /api/storage` | 在一致的数据库快照中返回额度及互斥占用分类 |
| `GET /api/files/{file_id}/status` | 单文件状态、清理进度或安全错误信息 |
| `POST /api/files/status-query` | 有界批量查询已加载文件的当前状态，避免全量加载历史 |
| `DELETE /api/files/{file_id}` | 原子检查下载占用并接受删除，或返回明确冲突 |

- `GET /api/files/{file_id}` 继续保留 Spec 002 的附件下载职责，不改为元数据接口；路由需正确区分 status 等路径。
- 文件列表默认 50 条，最大 100 条；按成功提交消息 ID 的排他游标查询，不使用会因删除而漂移的 offset。`GET /api/files` 接受 `limit`（1–100）和可选 `before`（正整数消息 ID），返回 `{ files, before, has_more }`；`files` 复用 FILE 消息字段，按数值消息 ID 降序，`before` 为本页最后一条的 ID，空页为 null。未知或非法查询参数返回 `400 invalid_query`，先认证再校验参数。
- 批量状态查询建议每批最多 100 个标识，遵循 Spec 001 共享认证矩阵：Web Cookie POST 须检查 Origin，原生有效 Bearer 可无 Origin；删除等管理接口同样按认证路径校验，不以缺失 Origin 本身作为身份。
- 认证分阶段交付：本切片实现并验收 Web Cookie 认证与 Origin 防护；原生 Bearer 及相关混合凭证场景随 Spec 005 的原生认证能力交付后补验，不要求提前实现原生凭证体系。
- DELETE 默认异步接受返回 202；重复删除中返回当前状态，已删除返回已完成，未知标识返回 404；活动下载返回 409/FILE_IN_USE，不自动延迟执行。
- DELETE 按文件当前状态处理重复请求，保证不重复清理或释放额度，但不提供删除操作结果的永久重放：之前因下载被拒绝的请求，在下载结束后重新调用可能成功。因此客户端不得自动重试结果未知的 DELETE；自动重试仅用于已接受删除的服务端实体清理。
- 用量、状态和列表均须鉴权，不使用可被共享缓存复用的用户数据响应；错误不暴露内部磁盘路径。
- 页面中删除进度查询建议每 2 秒，失败退避至最多 30 秒；认证失效停止，遵守服务端 Retry-After。
- 拒绝删除或结果未知均不能乐观释放容量；必须以服务端状态与用量快照校正。
- 批量校正历史状态只更新对应文件状态，不重新排列消息，不修改增量游标，不丢弃文本草稿或文件上传队列。
- 页面按 file_id 合并状态，只接受更高 state_version，等版本重复响应不回退状态。先合并版本再决定列表可见性；删除完成后的最小版本记录保留到本页面生命周期结束，避免迟到列表或历史响应重新插入已删除文件。
- 状态缓存只在认证后的界面使用，退出时清除，跨认证周期的迟到响应不得恢复显示。容量快照独立使用串行查询或请求代次防止旧响应覆盖新结果，不把文件版本当作全局容量版本。

## 4. 验收场景

| 编号 | 场景与预期 |
| --- | --- |
| M01 | 新到旧分批加载文件，状态与基本信息正确；删除完成从列表移除但历史保留 |
| M02 | 两个删除入口共用确认与服务端规则，不影响任何本地副本 |
| M03 | 活动下载期间删除返回冲突，文件保持可用且额度不变；下载结束后须再次主动删除 |
| M04 | 下载与删除同时竞争，恰有一致裁决：已有读取则拒绝删除，已接受删除则拒绝新读取 |
| M05 | 连接中断及读取错误释放句柄/计数，不出现永久“正在下载”；重启不保留虚假读取占用 |
| M06 | 删除响应丢失只自动查询，不自动重发 DELETE；丢失 FILE_IN_USE 响应后下载结束不触发自动删除；用户确认重试安全且不重复释放额度 |
| M07 | 删除中不能下载；实体清理失败保持占用并重试，不提前显示完成 |
| M08 | 持久标记后、实体删除后、额度释放前分别注入崩溃，恢复正确且仅释放一次 |
| M09 | 并发上传/删除下已保存、预留、待清理三类不双计或漏计；容量快照不代替上传准入检查 |
| M10 | 列表不承诺即时发现外部移除；按需访问发现异常并记录；确认存储健康后可显式删除缺失实体；全局权限或挂载异常不把全部文件标为缺失或释放额度 |
| M11 | 当前删除轮询、手动刷新及重入页面校正文件状态；隐藏/认证失效暂停，不改变消息顺序；应用内切页保留草稿、上传队列和未确认发送及删除状态，前台且认证有效时上传与队列调度继续，返回后状态保留 |
| M12 | 删除后重放原发送只返回原消息及已删除状态，不重新创建实体或消息 |
| M13 | 本阶段：未认证管理请求及 Web Cookie 错误/缺失 Origin 写操作被拒绝，标识不能越界访问磁盘。随 Spec 005 补验：原生有效 Bearer 无 Origin 可删除和批量查状态，Web Cookie 防护不变，混合凭证拒绝 |
| M14 | 文件列表、历史、发送结果和删除状态响应乱序时，旧版本不能恢复下载或重新插入已删除文件；旧容量响应不能覆盖新请求结果，退出前响应不能重新展示敏感内容 |

### 公共测试边界

遵循[测试原则](../testing.md)，通过以下边界验证本 Spec：

- 真实 HTTP API、隔离 SQLite 与文件目录：验证分页、鉴权、容量分类、重复删除、下载与删除竞争、存储异常、删除后发送重放及状态版本（M01、M03–M04、M07、M09–M10、M12–M13）。
- 必要的真实连接和子进程生命周期：验证断连与读取错误释放句柄，以及删除关键持久化边界崩溃后的恢复和仅一次额度释放（M05、M08）。
- 少量连接真实后端的 Playwright 流程：验证两个删除入口、未知结果只查询、状态及容量响应乱序、应用内导航和认证恢复（M02、M06、M11、M14）；网络拦截仅用于制造必要故障。
- 最新稳定版桌面 Chrome 人工验收确认文案、下载与删除反馈及页面状态；浏览器任务是否最终落盘不作为服务端活动读取的判断依据。

故障注入及破坏性验证仅使用隔离合成数据。断言公共接口及存储边界的可观察效果；验收编号与测试不要求一一对应，浏览器层不重复全部后端故障用例。

## 5. 审阅与完成条件

整份 Spec 已最终确认，包含删除请求与实体清理的重试区别、文件状态版本及迟到响应处理、存储异常的按需检测边界，以及服务端活动读取判定标准：不承诺跟踪 Chrome 最终落盘。

产品基线及 Spec 002 已同步阶段契约引用；Spec 001 的阶段扩展说明已补充本阶段状态版本约定，不追溯增加文本阶段验收要求。本 Spec 当前阶段范围实现并通过适用验收后完成该切片；M13 的原生认证部分随 Spec 005 补验，不作为本阶段完成前置条件。完成该切片不代表生产部署或 Android 已完成。
