# Spec 001：桌面文本闭环

状态：已确认，实施中。#6 隔离启动与显式初始化已建立，其他业务能力及阶段验收仍待完成。本文为桌面文本闭环的权威需求、技术契约与验收依据；确认不代表已经实现。

权威来源：本文件是该切片的唯一 Spec；[实施主 Issue #4](https://github.com/nt1r/FileHop/issues/4) 跟踪实施与验收，不复制或替代本文件。如迁移到 Issue，应明确迁移后的权威来源，不双份维护。

关联：[产品基线](../product.md) · [路线图](../roadmap.md) · [术语](../../CONTEXT.md)

## 1. 目标与范围

用户通过两个独立的桌面 Chrome 登录会话，完成发送文本、获取新消息、查看历史和复制正文。服务器持久保存消息，并在网络结果未知时支持无重复的同次重试。

包含：Compose 开发骨架、账户初始化与重置、Web 认证、文本消息、来源标签、分页历史、前台轮询、失败恢复及验证。

不包含：文件能力、Android、其他浏览器兼容承诺、搜索、编辑或删除消息、离线模式、持久化草稿、发送队列、后台同步、系统通知、公网生产部署验收、备份恢复。

### 后续文件阶段的契约扩展

[已确认的 Spec 002](002-desktop-file-transfer.md) 从文件阶段起将共享消息查询扩展为显式 TEXT/FILE 类型，并使发送结果查询支持文件消息。公共字段与分页语义保持不变；文件字段、上传尝试及页面文件队列以 Spec 002 为准。

[已确认的 Spec 003](003-server-file-management.md) 从文件管理阶段起为文件状态增加 state_version 及迟到响应合并规则，适用于历史和发送结果等包含文件状态的响应，不改变文本消息语义。

本 Spec 的消息字段描述和“不包含文件能力、发送队列”仅限定文本阶段，不禁止后续扩展，也不要求阶段 1 提前实现或验收文件功能。文本发送仍遵循本 Spec 的单次进行中操作限制。

[已确认的 Spec 004](004-web-production-deployment.md) 从生产发布阶段引入发布/API 兼容版本检查及最小稳定控制契约。不兼容的旧页面暂停新业务操作、保留内存输入并提示刷新；维护和兼容性检查不能把未知发送当成失败。这些升级验收属于阶段 3，不追溯增加阶段 1 的生产发布要求。

## 2. 已确认的开发与验收环境

- 开发机本身是 VPS，开发者远程连接该 VPS 工作；不需要从 VPS 到个人电脑的隧道。
- 使用独立开发域名 `filehop-dev.hammerbilly.top`，在部署配置中填写；域名已确认不代表 DNS 或接入已经配置。
- Caddy 在 VPS 上管理 SSL/TLS 证书与 HTTPS。
- 浏览器只访问开发域名的 HTTPS 443，前端使用同域相对地址 `/api/*`。
- 前端开发服务、Rust 后端不直接发布公网端口；通过 Compose 内部网络接受代理请求。
- 前端热更新若需要 WebSocket，通过同域 WSS 443；这不是业务消息同步使用 WebSocket。
- 后续部署讨论已确认公网仅开放 TCP 443、不开放 80，通过 Oracle Cloud 网络规则管理，不承诺 HTTP 跳转。共享 Caddy 使用兼容 443-only 的证书验证，具体部署设计见 [已确认的 Spec 004](004-web-production-deployment.md)。
- 开发和生产账户、密钥、数据及运行配置隔离；若共用 Caddy，使用独立站点路由，不让开发配置覆盖生产。
- 验收仅承诺当时最新稳定版桌面 Chrome；具体版本及测试系统保留在私有验收证据中，公开仅记录兼容类别和结果，除非另获公开许可。不承诺所有桌面系统组合。
- 容器内部遵循 `/data/database/transfer.db`、后端 `0.0.0.0:8080` 和 `backend:8080` 约定。

## 3. 账户与登录

### 初始化与重置

- 通过 Compose 内显式管理命令初始化数据库、受管存储身份和唯一账户，不提供网页注册或初始化向导。初始化时数据库目录与文件存储目录必须是操作者确认的目标位置。
- 普通启动或迁移不得因数据库缺失而自动创建替代实例；未初始化时仅提供安全诊断/初始化提示，不开放业务写入。首次合法空目录由初始化命令处理。
- 初始化只接受全新且一致的目标目录，拒绝覆盖已有数据库、存储标识或未知残留。跨目录初始化失败须报告部分完成状态，禁止自动清空目录重来，由操作者检查后处理。
- 数据库与文件根目录保存可核对的本地存储标识，正常启动验证匹配、可访问及必需文件存在；缺失或不匹配失败关闭相关写入，不将其视为新的空实例。该标识用于本机防误挂载，不增加客户端多服务器身份管理。
- 管理员设置用户名及密码；无默认账户或默认密码。
- 密码通过隐藏输入读取，不置于命令行参数或日志。
- 已存在账户时拒绝重复初始化，不覆盖原账户。
- 未初始化时 Web 提示管理员先初始化，不开放远程创建账户。
- 独立重置密码命令撤销全部现有登录，不删除消息及发送标识。

### 凭证规则

- 密码为 12–128 个 Unicode 码点，允许中文及空格，不自动 trim，不强制字符类别组合。
- 用户名为 3–32 个 ASCII 字符，仅字母、数字、`_`、`-`；统一转小写后保存和匹配，不自动去除空格。
- 登录请求体上限默认 8 KiB，超过上限直接拒绝；与密码码点长度限制分别校验。
- 登录失败统一提示“用户名或密码错误”，不泄露是哪一项错误。
- 按来源地址实施失败节流，并限制全局密码验证并发；不因错误次数永久锁定唯一账户。
- 安全 Cookie 会话固定有效 12 小时，不自动续期；凭证、哈希和密码不写日志。
- 普通服务重启不无故撤销尚未过期的登录。
- 支持退出当前登录，其他会话不因此失效。

### 到期与主动退出

- 检测到登录失效后暂停业务请求，隐藏消息内容，提供当前页面内的重新登录入口。
- 区分认证失效和网络故障，网络错误不能直接当作退出登录。
- 草稿及未确认发送暂存在当前页面内存，不在未认证界面展示。
- 重新登录后刷新历史、恢复输入，不自动发送草稿。
- 未确认发送先确认原结果或使用原发送标识重试，不换新标识悄悄重发。
- 主动退出前提示未保存内容；用户确认后立即清除本页面消息、草稿和发送状态，停止业务请求，并通知同源其他标签页清理页面。其他独立浏览器会话不受影响。
- 若退出请求结果未知，进入“退出未确认”界面，提示当前页面已清空，但服务器登录状态尚未确认撤销，提供重试退出，不自动恢复展示业务数据。
- 已收到主动退出通知的同源标签页同样进入退出待确认状态，保持内容清空并暂停自动恢复业务展示；即使回到前台后 Cookie 仍有效，也不能自动恢复历史。退出结果未知时提供重试退出；任一标签页确认服务器已撤销会话或会话已失效后，通知其他同源标签页进入普通登录界面。不增加持久化退出锁，刷新或新开页面仍可能识别到有效登录。
- 服务端确认撤销或会话已经失效后，进入普通登录界面。结果未知时刷新页面仍可能识别到有效登录，不能把隐藏页面当作凭证已撤销。
- 退出接口可重复调用；凭证已失效或不存在时也应清除 Cookie 并返回退出完成。
- 主动退出或登录失效后，迟到的读取响应不得恢复显示历史；主动退出后的发送响应也不得恢复已清除的输入状态。

## 4. 输入与复制

- 拒绝空字符串和纯空白文本，合法文本原样保留，不自动 trim、改缩进或截断。
- 空白集合固定为 Unicode White_Space 对应码点：U+0009–U+000D、U+0020、U+0085、U+00A0、U+1680、U+2000–U+200A、U+2028、U+2029、U+202F、U+205F、U+3000。前后端使用相同集合与测试样例；零宽空格 U+200B 和 BOM U+FEFF 不在该集合内。
- 文本上限 65,536 字节，按实际发送的 UTF-8 文本计量；前端预检，服务端强制校验。
- Enter 换行；Ctrl+Enter / Cmd+Enter 发送；提供发送按钮。输入法组合输入期间不得误触发送。
- 以纯文本显示，保留换行，不解释 HTML 或 Markdown，不抓取 URL 内容。
- 复制完整正文，不附加时间和来源标签；剪贴板失败应提示，不能显示虚假的复制成功。

## 5. 发送尝试与状态

### 基本规则

- 单个页面最多一条进行中或结果未确认的发送，不限制其他会话独立发送。
- 发起发送时固定发送标识、正文和来源标签；请求中禁止重复点击。
- 同次重试携带原标识与原载荷。发送身份不属于某次登录。
- 同标识、同载荷返回原结果；同标识、不同载荷拒绝，不覆盖原消息。
- 成功发送的标识随消息持久保存，不因登录到期或服务重启失效。
- 主动再次发送相同内容属于新操作，使用新标识，不按文本内容去重。

### 用户可见状态

| 状态 | 输入与动作 |
| --- | --- |
| 草稿 | 可编辑，符合校验规则后可发送 |
| 发送中 | 固定载荷，禁止重复发送 |
| 已成功 | 展示服务器消息，清空输入 |
| 明确拒绝且确定未保存 | 保留内容，可编辑并发起新的发送尝试 |
| 结果未确认 | 固定原载荷，可用原标识重试或放弃确认 |

- 普通发送只有确认成功后才自动清空仍属于该次发送的输入；主动退出等显式丢弃行为按各自规则处理。HTTP 超时、断连或不明确的服务错误不能自动当作“确定未保存”。
- 不自动无限重试写请求；用户触发发送重试。网络恢复可以恢复读取历史。
- 放弃确认前提示原消息可能已经保存，请先检查历史；解除输入锁定，但不自动重发。
- 放弃确认不是撤回，不能取消已经提交的服务器消息。原正文保留为可编辑草稿，提示再次发送可能重复；再次主动发送使用新标识。
- 放弃后的原请求若迟到成功，只校正消息列表，不清空或覆盖新草稿。
- 服务端在事务成功提交后才报告成功，写入失败不报告成功。
- 查询成功结果或同次重试可以确认未知结果；一次查询未找到不能证明在途请求不会随后提交。
- 已认证的历史或增量读取若返回与当前发送尝试的发送标识、正文及来源标签均匹配的服务器消息，同样直接确认发送成功，无需额外查询或重试。仅清空仍属于该次发送的输入；若已放弃确认，则只合并消息，不清空或覆盖新草稿。

## 6. 页面内存与来源标签

### 草稿生命周期

- 草稿及未确认发送仅在当前页面生命周期内保留，不存入 localStorage 或 IndexedDB。
- 网络故障和同页重新登录不清除它们。
- 刷新或关闭页面可能丢失未保存内容；存在未保存内容时尽力提供离开提醒，不承诺浏览器一定展示。
- 刷新后拉取服务器历史，不自动重发旧内容，也不承诺从重新输入的文字推断原发送身份。

### 来源标签

- 默认 `Web`，消息页提供轻量编辑入口，不建设设备管理页。
- 标签按第 4 节的空白集合去除首尾空白后，长度须为 1–64 个 Unicode 码点；显示和保存规范化后的值，不对正文或密码进行此处理。
- 标签在创建发送尝试之前完成规范化，同次重试保持固定值。
- 按当前浏览器配置持久保存，允许同源标签页共享；不同步到其他设备。
- 发起发送时固定标签，修改不改变历史消息或当前未确认发送的载荷。
- 标签不参与认证授权，不识别物理设备。

## 7. 历史列表与前台同步

- 聊天式布局，最新消息在底部，首次加载最近 50 条并定位到底部。
- 点击“加载更早消息”每次加载 50 条，不做无限滚动；50 是分页大小，不是保留上限。
- 服务器决定稳定顺序，不依赖客户端时钟。
- 加载旧消息保持阅读位置；位于底部时跟随新增消息，否则不抢滚动，提供“回到最新”入口。
- 不计算未读数量，不维护已读状态。
- 前台可见时每 10 秒检查新增消息，进入前台及手动刷新时刷新；隐藏时停止常规定时轮询。
- 网络失败有提示并退避重试。不能因一次拉取失败丢弃既有历史或推进游标。
- 读取新消息与发送响应可能返回同一条记录，列表必须去重。
- 离开较久后，增量消息超过一页也应补齐，不能直接跳到最新而永久漏掉中间消息。

## 8. 持久化与安全边界

- 成功响应以数据库事务提交为前提；消息与对应发送标识原子保存。
- 正常重启、保留数据卷的容器重建、后端进程异常退出后，已确认消息和发送标识保留。
- 不承诺硬盘损坏、数据目录丢失后的恢复，不要求真实主机掉电演练；仍需采用合适的 SQLite 持久化配置。
- 业务接口须鉴权，Cookie 设置 Secure、HttpOnly、SameSite，写操作有 CSRF 防护。
- 反向代理来源地址只信任受控 Caddy，不能用客户端可伪造的头绕过节流。
- 开发数据、敏感配置不提交 Git；请求日志不记录文本正文或凭证。
- 开发域名可能公网可达，开发服务、热更新资源及错误详情的暴露范围须在开工前检查；业务登录不能被当作保护整个开发服务器的替代品。

## 9. 最小技术契约与实现默认方案

本节已随整份 Spec 确认。接口和行为契约变更需更新 Spec；参数默认值及内部实现可经测试调整，但不能改变前述产品语义或安全边界。

### 运行结构

- Compose 管理前端开发服务和 Rust 后端，SQLite 无独立容器；Caddy 作为独立入口运行，可使用独立 Compose 或宿主服务。独立宿主入口不得影响无关服务，运行方式见[宿主入口指南](../host-ingress.md)。
- Caddy 将 `/api/*` 路由至后端（应用网络内服务名 `backend:8080`；宿主入口使用专用网络固定内部地址），其余页面和热更新流量代理到前端服务。应用容器内端口和路径契约不变。
- 开发域名在 Caddy 层启用独立 HTTP Basic Auth，覆盖页面、API 和热更新握手，凭证与 FileHop 账户不同，仅通过 HTTPS 使用。
- Caddy 保存外层密码哈希，真实凭证及哈希配置不提交 Git；转发前移除用于外层认证的 Authorization 头。
- 外层拒绝使用可识别标记，不能被客户端误判为 FileHop 会话到期；浏览器可能先处理 Basic Auth 挑战，客户端遇到无有效应用错误格式的响应应提示访问层异常，而不是清空草稿。
- 应用退出只撤销 FileHop 会话，不宣称清除浏览器缓存的 Basic Auth。生产站点不自动继承此外层门槛；以后可另行改为 VPN 或 IP 限制。

### 共享认证矩阵

本节为共享接口的认证基线，文件阶段及 Android 阶段引用此表，不重复实现互相冲突的 Origin 规则。

| 请求类别 | 认证与 Origin 规则 |
| --- | --- |
| Web Cookie 业务请求 | 校验 Web 会话；写请求严格验证配置的精确 Origin |
| 原生 Bearer 业务请求（Spec 005 起） | 校验原生会话类型、摘要及有效期，可无 Origin；不能仅因缺失 Origin 放行 |
| 同时提供应用 Cookie 与 Bearer | 拒绝歧义，不回退另一种认证 |
| Web 登录 | 用户名密码、JSON、精确 Origin；成功设置安全 Cookie |
| 原生登录（Spec 005 起） | 独立 JSON 用户名密码入口，不接受 Cookie 作为身份、不设置 Web Cookie；可无 Origin，不开放跨域浏览器访问 |
| 开发 Basic Auth | 仅为 Caddy 外层门槛，不代替应用认证；映射规则遵循 Spec 005 |

文件上传、停止、服务器删除及只读批量状态 POST 均按所选应用认证路径执行，不对合法原生 Bearer 强制 Web Origin。两端共享限流、授权与敏感数据保护。公共初始化/版本信息仅返回明确允许公开的最小信息，不据此放行业务。

### 认证与存储

- SQLite 保存唯一用户、服务端会话和文本消息；会话使用随机不透明 Cookie，数据库保存凭证摘要及固定到期时间。
- 密码使用 Argon2id；Cookie 采用 host-only、Path=/、Secure、HttpOnly、SameSite=Lax。
- 本阶段所有应用写接口（包括登录和退出）仅接受配置的精确同源 Origin；缺失、null 或不匹配时拒绝，不根据任意 Host 头动态决定可信源。JSON 写请求要求 application/json，不开放跨域凭证访问；SameSite 作为补充防护。Android 阶段按[Spec 005](005-android-text-loop.md) 增加独立原生会话及 Bearer 认证路径：有效原生凭证可无 Origin，Web Cookie 路径仍严格检查 Origin，混合凭证拒绝；不能仅凭缺少 Origin 绕过防护。不要求本阶段提前实现原生认证。
- Cookie 使用随机高熵不透明凭证，数据库只保存摘要；退出删除对应会话并清除 Cookie。认证响应及包含用户内容的响应使用 Cache-Control: no-store。
- SQLite 建议 WAL + synchronous=FULL，使用事务和迁移，不将数据库文件置于临时容器层。
- 消息包含服务端递增 ID、正文、来源标签、服务器时间及客户端发送标识；发送标识唯一约束和原子事务处理并发重试。
- 同标识不同载荷的检查基于保存的正文及来源标签，不依赖客户端声明。

### 接口职责与数据契约

| 接口 | 职责 |
| --- | --- |
| `GET /api/status` | 最小初始化状态，不泄露配置或凭证 |
| `POST /api/session` | 登录并设置 Cookie |
| `GET /api/session` | 当前认证状态与到期时间 |
| `DELETE /api/session` | 撤销当前登录并清除 Cookie |
| `POST /api/messages` | 携带发送标识、正文和来源标签发送文本 |
| `GET /api/messages` | 最近页、before 历史分页或 after 增量分页 |
| `GET /api/sends/{send_id}` | 查询已成功的发送结果，不把“未找到”当成取消证明 |

- `GET /api/status` 返回 `{ "state": "uninitialized" | "initialized" | "storage_error" }`，使用 `Cache-Control: no-store`；仅诊断初始化状态，不表示登录或全部业务就绪。存储缺失、不匹配、部分初始化或不可访问统一报告 `storage_error`，不返回路径、用户名或凭证；空且合法的一致目录为 `uninitialized`。页面提供手动刷新，不提供远程注册或初始化。
- 发送请求包含 `send_id`（客户端随机 UUID）、`text`、`source_label`。消息响应包含 `id`、`send_id`、`text`、`source_label`、`created_at`；时间用 UTC RFC 3339，消息 ID 在 JSON 中用十进制字符串，避免 JavaScript 整数精度问题。
- 列表支持 `limit`（默认 50，范围 1–100）、互斥的 `before` 或 `after`（排他边界）。消息返回顺序统一为 ID 升序。
- 首次及 before 查询选取边界前最近一页，返回 `has_older` 和最小 ID 作为继续向前的游标；after 查询选取边界后最早一页，返回 `has_more` 和本页最大 ID 作为继续向后的游标。
- 首次读取同时返回同一数据库快照的 `sync_cursor`，即该快照最大消息 ID；历史为空时为 `0`。这样加载前 50 条不是漏消息，旧历史仍由 before 加载。
- 历史分页游标与新增读取游标分离；增量只在整页成功合并后推进到本页最大 ID，空页不推进；本地发送响应和结果查询不能推进增量游标。
- 多页新增按顺序补齐，不并发推进同一游标；响应与本地消息按 ID 合并去重。
- 相同发送标识的重放仍须重新认证，不能仅凭标识读取消息。
- 应用错误返回结构化 `code` 与安全的 `message`，不泄露内部 SQL 或敏感详情。明确输入拒绝使用 400/413/422，未认证 401，同源检查拒绝 403，发送标识冲突 409，节流 429；具体 code 在实现中作为稳定契约测试。
- HTTP 状态本身不能证明原发送未保存：401/403/429 仅说明本请求未执行；以前已提交但响应丢失的同次请求仍可能存在。409 显示冲突，不自动换标识重发；超时、断连、无法解释的响应和 5xx 保持结果未确认。
- 查询未找到返回结构化 404，不代表在途请求已取消。新建发送返回 201，同载荷重放返回 200，均返回原始服务器消息。

### 可调默认参数与实现检查

- 文本发送 JSON 请求体上限默认 512 KiB，以容纳 64 KiB 正文的 JSON 转义开销；解码后仍强制正文及标签限制。登录请求体上限默认 8 KiB。
- 登录失败默认按来源地址在滚动 15 分钟内允许 10 次失败，达到限制后返回 429 与 Retry-After；不永久锁定账户。限制并发验证的默认上限为 2，无界队列不可用，过载快速拒绝。并发请求也不得绕过计数边界。
- 失败计数允许重启后重置；不存在的用户名执行等价的虚拟密码验证，避免显著的用户枚举差异。Argon2id 参数按 VPS 资源测量，记录选择与并发内存预算，不靠猜测承诺耗时。
- Caddy 覆盖传入的客户端来源头，后端仅信任内部受控代理；若有额外上游代理，部署前单独核实信任链，不默认信任任意 X-Forwarded-For。
- 文本及 JSON 控制/状态读取请求客户端整体超时默认 15 秒，仅适用于短请求，不适用于文件上传或下载响应体。客户端超时不代表服务端回滚。登录默认 30 秒；Web 登录响应未知不盲目连续创建会话，应先检查当前会话；原生登录响应丢失遵循 Spec 005 的独立规则。
- 文件传输使用 Spec 002 的独立连接、无进展及整体期限策略，不能把这里的 JSON 超时配置为所有 HTTP 请求的统一总时限。
- 读取错误按 10、20、40、60 秒退避并加入小幅抖动，上限 60 秒；成功后恢复 10 秒。尊重 Retry-After；同一同步任务不重叠，分页补齐每页成功后继续，失败保留进度。
- 手动刷新及回到前台可立即读取，但不得绕过服务端明确的 Retry-After 限制。登录失效暂停同步，重新登录后重新建立一致的历史与增量基线。
- 测试工具由实现选择：必须覆盖真实 SQLite 的事务/分页/并发重试及独立浏览器上下文的关键流程，不能只用 Mock 验证核心一致性。
