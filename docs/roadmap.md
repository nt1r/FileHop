# FileHop 第一版交付路线图

状态：需求基线已确认，Spec 001 已开始实施，隔离启动与显式初始化闭环已建立；阶段尚未验收完成。

相关文档：[产品基线](product.md) · [领域术语](../CONTEXT.md) · [测试与交付质量原则](testing.md)

## 交付原则

- 可用性优先，按可验证的纵向切片交付，不采用“完整后端 → 完整前端 → 最后部署”的顺序。
- 桌面 Web 是中间交付点；Android 完成才覆盖电脑与手机的核心闭环。手机浏览器不在支持承诺内。
- Compose 从开始使用；认证、安全、失败处理随相关功能交付，不集中留到最后。
- HTTPS、部署可提前验证，阶段表描述退出目标，不是严格的技术施工顺序。
- 每个切片有主 Spec Issue；阶段不另建重复需求文档。
- 实现及验收遵循测试与交付质量原则：后端真实集成测试为主、少量客户端端到端和必要人工验证，按风险逐步补齐，不预建全部测试框架。
- 六份 Spec 已确认；实现任务按近期阶段逐步细化，不把远期内部实现一次性锁死。
- 当前不要求备份恢复，也不以未来探索功能作为项目完成条件。

## 阶段 1：桌面文本闭环

目标：带认证、可持久化的桌面文本交换。

权威需求：[Spec 001：桌面文本闭环](specs/001-desktop-text-loop.md)。运行骨架与显式初始化作为实现子任务，不再拆出重复需求文档。

覆盖内容：

- Compose 运行骨架、开发数据目录与账户初始化。
- 用户名密码登录、12 小时固定有效期、退出、管理命令撤销登录、登录节流。
- 文本发送、主动复制、来源标签、分页历史。
- 同次发送重试不重复创建消息。
- 前台 10 秒轮询、进入页面和手动刷新、网络异常退避。

退出标准：

- 两个桌面浏览器会话可以交换文本。
- 未认证或已失效凭证不能访问业务数据。
- 文本长度边界与重试行为可验证。
- 正常服务重启后历史保留。
- 开发数据与密钥不进入版本控制。

认证、文本、游标、兼容范围及重试契约已在 Spec 001 确认；实施前选择测试工具、配置具体运行参数并验证环境。

## 阶段 2：桌面文件闭环

目标：可以传文件，并可控制服务器文件占用。

已确认的 Spec：

1. [Spec 002：文件传输与容量控制](specs/002-desktop-file-transfer.md)，包含流式上传下载、容量及异常清理。
2. [Spec 003：服务器文件管理与删除](specs/003-server-file-management.md)。

容量和异常处理是完整文件闭环的必备部分，不能把不受控上传视为阶段完成；实现任务可拆分，但不另设重复 Spec。

退出标准：

- 桌面客户端可上传并下载文件，展示基本信息；页面展示上传进度与错误，下载进度和结果允许由浏览器原生下载管理器提供。
- 服务端内存不随上传文件体积线性增长。
- 默认单文件 100 MiB、文件额度 1 GiB 的边界及并发约束有验证。
- 服务器提交前上传中断不产生文件消息，临时数据得到清理。
- 服务器提交后成功响应丢失，消息仍保留，客户端将结果视为未确认；结果查询或同次重试可确认结果，且不重复创建消息。
- 文件管理页能列出文件、展示用量、下载和单个删除。
- 服务端接受删除后即禁止新的下载；历史记录区分“删除处理中，空间尚未释放”和清理完成后的“服务器文件已删除”。
- 删除不影响已下载副本；磁盘清理失败有重试，不误报实体已删除，也不提前释放额度。
- 路径穿越、未经认证下载、异常文件名等场景得到验证。

提交一致性、容量预留、崩溃清理、删除并发及状态校正已在 Spec 002、003 确认；实施前确定可调资源参数并建立故障注入验证。

## 阶段 3：Web 生产部署

目标：桌面 Web 可通过正式域名自用。

权威需求：[Spec 004：Web 生产部署与发布](specs/004-web-production-deployment.md)。

退出标准：

- `https://filehop.hammerbilly.top` 提供桌面 Web、同域 API 和认证文件访问。
- 共享 Caddy 提供静态资源及内部反向代理，HTTPS 和证书自动管理兼容公网仅 TCP 443 的约束，不承诺 HTTP 跳转。
- GitHub 托管 CI 从受控 main 版本 tag 构建并发布 ARM64 产物至 GHCR，VPS 手动脚本部署；dev/main 分支保护生效，失败人工处理，不提供自动回滚。
- 后端无直接公网端口，SQLite 无独立数据库容器。
- 开发与生产使用独立数据挂载及配置，容器内部路径与端口契约一致。
- 容器重建后消息与文件仍可用。
- 提供初始化、运行、部署、更新与配置说明；说明明文存储和无备份恢复承诺。
- 桌面 Web 上的文本、文件、删除、认证到期与前台同步完成端到端验证。

不要求：手机 Web 适配、备份恢复、后台同步。

## 阶段 4：Android 核心交付

目标：完成桌面 Web ↔ 服务器 ↔ Android 的核心闭环。

### 切片 A：认证与文本

- Kotlin + Jetpack Compose。
- 独立可撤销登录凭证、12 小时固定有效期、退出。
- 分页消息、文本发送与主动复制、来源标签。
- 前台 10 秒轮询、重新进入及手动刷新、异常退避。

验收：桌面 Web 与 Android 可双向交换文本；登录有效期、凭证存储与前后台切换行为符合 Spec。

### 切片 B：文件与本地下载

- 系统文件选择器上传，认证下载，前台进度与失败提示。
- 访问共享服务器文件并提供与权限范围一致的下载和删除入口，具体导航布局在 Spec 中确定。
- 本地下载列表，只管理应用保存且有访问权限的副本。
- 本地副本打开和删除，不影响服务器或其他设备。

验收：

- 桌面 Web 与 Android 可双向上传、下载文件。
- 服务器文件删除和本地副本删除的影响范围不同且有清楚提示。
- 前台中断、未知发送结果、重新尝试、凭证到期等行为符合约定。
- 不依赖后台服务、系统分享入口或手机浏览器才能完成核心场景。

权威需求：[Spec 005](specs/005-android-text-loop.md) 与 [Spec 006](specs/006-android-files.md)。最低版本、凭证规则、文件选择/存储/生命周期及外部打开边界已确认；具体 SDK、存储保护 API 和资源参数在实现前验证。

## 核心项目完成判定

阶段 1–4 退出标准通过，且产品基线中当前范围内的行为均有对应验收证据，即可宣布核心项目完成。

Wasm、SSE、分片、后台同步等不构成待清空清单；未来有真实需求时另开 Spec。备份恢复及系统分享入口当前也不作为增强承诺。
