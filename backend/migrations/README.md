# 数据库迁移维护规则

本目录使用 SQLx migrations 管理生产数据库结构及必要的基础数据。发布与部署流程以 [Spec 004](../../docs/specs/004-web-production-deployment.md) 为准。

## 编号与冻结

- 开发中的新迁移命名为 `NNNN_next_release.sql`，例如 `0001_next_release.sql`。数字版本全局递增，不是 Issue、Spec 或应用发布版本；四位补零用于阅读，不限制后续版本数量。
- 发布准备时，通过正常 PR 在 `dev` 上把本轮新迁移定名为 `NNNN_vMAJOR_MINOR_PATCH.sql`，例如 `0001_v0_1_0.sql`。只修改描述部分，不改变数字版本；在 `dev → main` 发布 PR 合入前完成定名及验证，不把 `next_release` 文件带入 `main`。
- 不在每次发布后从 `0001` 重新编号。发布构建不得再次改名；历史文件保留首次交付的发布版本，不随后续发布重命名。编号不作为“表结构 / 数据 / 测试数据”的永久分类槽位。
- 尚未进入 `main` 的迁移默认允许原地整理；一次开发周期不要求每次修改都新增文件。合并前检查编号唯一性、执行顺序及并行分支冲突。
- 迁移一旦进入 `main`，其文件名、版本号及内容在所有分支上冻结，包括后续的 `dev`。不得改写、删除或复用其编号；后续数据库变更新增迁移。
- `main` 是冻结点，不是生产部署证明。进入 `main`、打 tag 发布、生产部署和数据库迁移成功是不同事件。

示例：首轮 `0001_next_release.sql` 在发布准备时定名为 `0001_v0_1_0.sql`；下一轮保留该文件，新增 `0002_next_release.sql`，准备下一次发布时定名为 `0002_v0_2_0.sql`。同一发布可包含多个不同数字版本的迁移，不强制每个发布只有一个文件；没有数据库变更时不创建空迁移。

## Checksum 与开发数据库

SQLx 在 `_sqlx_migrations` 中保存已应用迁移及 checksum；运行迁移器时校验历史并执行待应用迁移。迁移以数字版本识别，checksum 根据 SQL 内容计算，文件描述不参与 checksum。仅在发布准备时修改描述部分、保持数字版本及 SQL 内容不变，不会重新执行已应用迁移或单独引起 checksum 冲突；数据库中原有的描述可能仍为 `next release`，不得为同步描述而手工改写历史记录。修改已应用 SQL 内容不会让 SQLx 自动重新执行它，可能导致 checksum 不匹配。

改写尚未冻结的迁移后，只能由操作者显式重建已确认可丢弃的开发/测试实例，并重新走初始化流程。清理前核实解析后的数据库与文件目录，二者按受管存储身份一起处理。开发环境可丢弃不等于任何开发数据都已获删除授权。

禁止通过自动清库、自动接受新 checksum 或手工修改 `_sqlx_migrations` 绕过不一致；不能对需要保留的数据套用重建办法。测试通过公开管理命令和应用 interface 验证新实例初始化；新增升级迁移时也须验证旧版本数据升级及保留。

## 数据分类

- 表、索引和约束由生产迁移管理；发布前可以集中整理，冻结后通过新增迁移演进。
- 所有环境必需的固定、非敏感基础数据可按需单独迁移；没有实际需求时不创建空的 seed 文件。
- 唯一账户、密码哈希、受管存储标识由显式初始化命令生成，不作为固定生产 seed；真实用户内容、凭证和环境专属配置不得进入迁移文件。
- 开发/测试合成数据不放入本目录：SQLx 不会按文件名自动跳过“开发数据”。优先通过公开 interface 创建测试数据，确需 SQL fixtures 时独立放在 `backend/fixtures/`，由显式测试/开发入口加载，不能随生产初始化自动执行。目前未建立此目录或加载命令。

## 执行与发布记录

当前 `sqlx::migrate!("./migrations")` 在编译时嵌入迁移；`init` 在运行时显式执行迁移器。普通 `serve` 不自动迁移，也不进行迁移 checksum 校验；不能重复执行 `init` 来升级已有实例。

已有实例的独立升级入口尚未实现，后续按 Spec 004 实现存储身份验证、旧后端停止后的迁移及失败保持维护。迁移失败不自动清库、自动回滚或盲目重试。

发布清单应将应用版本、确切 Git SHA 与完整迁移集合关联，列出数字版本、已定名文件名和 SQLx checksum，以便核对产物内容。文件名中的发布版本表示该迁移首次交付归属，不代替清单或生产执行记录；发布只消费已定名、已验证的提交，不在构建中改写文件。清单生成及命名/冻结规则的自动检查尚未实现。

- 发布清单 / tag：说明该发布包含哪些迁移。
- 目标数据库 `_sqlx_migrations`：说明该数据库记录了哪些已执行迁移及结果。
- 部署记录 / 运行发布标识：说明生产当前部署哪个应用版本。

文件存在或发布完成不能代替生产迁移成功的证据。
